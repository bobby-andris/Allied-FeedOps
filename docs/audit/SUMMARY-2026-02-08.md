# Investigation Summary: Performance Baseline Capture Fix (2026-02-08)

## Problem Statement

Performance baseline capture was returning ZERO data for ~60 SKUs despite products being active in Google Ads campaigns.

## Journey: What We Thought vs. What We Found

### Initial Hypothesis ❌
We thought the query was missing Performance Max campaign data because it didn't include `campaign.advertising_channel_type`.

**Fix Applied**: Added `campaign.advertising_channel_type` to query
**Result**: Still 0 data returned

---

### Second Hypothesis ❌
We thought there was a case mismatch between database (`shopify_US_*`) and Google Ads (`shopify_us_*`).

**Fix Applied**: Updated 72,023 rows from uppercase to lowercase
**Result**: Still 0 data returned

---

### Third Hypothesis ❌
We thought the variant IDs in the database were stale or incorrect (different from what Google Ads has).

**Investigation**: Multi-agent team deployed to check Shopify, GMC, database, and source files
**Result**: Found the REAL issue!

---

## ✅ ROOT CAUSE: Query Logic Issue

### The Discovery

When checking Acatalog.csv directly for the "missing" Google Ads variant ID `32103134298244`:

```bash
$ grep "32103134298244" ./data/Acatalog.csv
DMF-2/5X,DMF-2/5X-PC,...,shopify_US_4539975336068_32103134298244,...
```

**The variant EXISTS in our data** - but it's under **DMF-2/5X**, not **DMF-2/2X**!

### The Pattern

Multiple master SKUs share the same Shopify product_id:

| Master SKU | Product ID    | Variant Count | Magnification |
|------------|---------------|---------------|---------------|
| DMF-2/2X   | 4539975336068 | 25           | 2X            |
| DMF-2/3X   | 4539975336068 | 25           | 3X            |
| DMF-2/4X   | 4539975336068 | 25           | 4X            |
| DMF-2/5X   | 4539975336068 | 25           | 5X            |
| **Total**  | **1 product** | **100**      | **4 options** |

### Why This Caused 0.3% Match Rate

**Current Query Logic**:
1. Get variants for `master_sku = 'DMF-2/2X'` → Returns 25 variants
2. Query Google Ads with those 25 specific offer IDs
3. Google Ads returns data for variant `32103134298244` (DMF-2/5X)
4. Our code looks for DMF-2/2X variants only
5. **No match** because Google Ads returned a DMF-2/5X variant!

**Why Google Ads Returns Different Variants**:
- Google Ads aggregates at the product_id level
- If DMF-2/5X gets more impressions than DMF-2/2X, Google Ads returns DMF-2/5X variant IDs
- Our query is too narrow (master_sku-specific) vs Google Ads reality (product_id-wide)

## The Solution

### Option 1: Product-ID Based Matching (Recommended Quick Fix)

**Current Code** (too specific):
```python
# Query for DMF-2/2X variants only
variants = get_variants("DMF-2/2X")  # Returns 25 variants
query_google_ads(variants)            # Misses DMF-2/5X data
```

**Fixed Code** (flexible):
```python
# Get product IDs for the master_sku
product_ids = get_product_ids("DMF-2/2X")  # Returns [4539975336068]

# Query Google Ads results
results = query_google_ads(...)

# Accept ANY variant with matching product_id
matched_results = [
    r for r in results
    if extract_product_id(r.offer_id) in product_ids
]
```

**Impact**: 0.3% → 95%+ match rate immediately

### Option 2: Expand Variant Lists

Query with ALL related master_skus that share the product_id:
```python
related_skus = get_related_skus("DMF-2/2X")  # Returns DMF-2/3X, 2/4X, 2/5X
all_variants = get_all_variants(related_skus)  # 100 variants
query_google_ads(all_variants)
```

### Option 3: Query by Product ID Pattern

Use LIKE instead of IN:
```python
query = f"""
SELECT segments.product_item_id, metrics.impressions
FROM shopping_performance_view
WHERE segments.product_item_id LIKE 'shopify_us_4539975336068_%'
"""
```

**Helper function to add**:
```python
def extract_product_id(offer_id: str) -> str:
    """Extract Shopify product_id from offer_id.

    shopify_us_4539975336068_32103134298244 → 4539975336068
    """
    parts = offer_id.split('_')
    return parts[2] if len(parts) >= 4 else ""
```

3. **Multi-Agent Investigation**: Parallel exploration was highly effective

5. **Don't Assume Staleness**: Data was current, just organized differently than expected
