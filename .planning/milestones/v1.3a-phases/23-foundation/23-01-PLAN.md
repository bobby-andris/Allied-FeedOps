  <name>Task 1: Fix OpenAI provider — temperature/reasoning conflict, json_schema, cache retention</name>
  <files>src/feedops/providers/openai_provider.py</files>
  <action>
Fix 3 bugs in `openai_provider.py`:

**Bug 1 (GPT52-01): Temperature/reasoning_effort conflict**
Lines 172 and 183 always pass `temperature=0.7`. When `reasoning_params` also contains `reasoning_effort`, this creates a conflict — GPT-5.2 treats them as mutually exclusive.
- When `reasoning_params` is non-empty (reasoning_effort is set), do NOT pass `temperature`.
- When `reasoning_params` is empty, pass `temperature=0.7` as before.
- Implementation: Build a `sampling_params` dict conditionally — if reasoning_params has keys, sampling_params is empty; otherwise sampling_params = {"temperature": 0.7}. Then spread `**sampling_params` in both API calls (image and non-image paths).

**Bug 2 (GPT52-03): json_schema strict mode instead of json_object**
Lines 171 and 182 use `response_format={"type": "json_object"}`. Replace with json_schema strict mode.
- Change response_format to use the `json_schema` type with the CANDIDATE_SCHEMA.
- The schema must be passed through a helper that converts the existing CANDIDATE_SCHEMA dict into OpenAI's strict json_schema format: `{"type": "json_schema", "json_schema": {"name": "candidate_content", "strict": True, "schema": <adapted_schema>}}`.
- The adapted schema needs `"additionalProperties": false` on every object (required for strict mode) and all properties must be listed in `required`.
- Import CANDIDATE_SCHEMA from `feedops.pipeline.prompts`.
- Create a module-level function `_build_strict_schema()` that converts CANDIDATE_SCHEMA into the strict format (add additionalProperties: false recursively to all object types, ensure all properties are in required arrays).
- Store the result in a module-level variable (computed once at import time) to avoid rebuilding per-request.
- IMPORTANT: Keep `response_format={"type": "json_object"}` as a fallback method `_build_response_format()` that returns json_schema when available and json_object otherwise — in case schema validation needs a fallback during transition.

**Bug 3 (GPT52-04): prompt_cache_retention**
Add `extra_body={"prompt_cache_retention": "24h"}` to both `client.chat.completions.create()` calls (image and non-image paths). This keeps the cached prefix alive between SKUs during batch runs instead of expiring in 5-10 minutes.
- Pass as `extra_body` parameter (OpenAI SDK passes unknown params to API via extra_body).

All three fixes apply to the same two `client.chat.completions.create()` calls in the `generate()` method (lines 168-175 for image path, lines 179-186 for non-image path).

Fix 2 bugs:

**Bug 4 (GPT52-02): Default reasoning_effort when env var unset**
In `optimize.py` line 148: `reasoning_effort = os.environ.get("FEEDOPS_REASONING_EFFORT")` returns None when unset, causing zero reasoning.
- Change to: `reasoning_effort = os.environ.get("FEEDOPS_REASONING_EFFORT", "medium")`
- This ensures GPT-5.2 uses medium reasoning by default. Users can still override via env var.

**Bug 5 (GPT52-05): Convert SYSTEM_PROMPT from === headers to XML tags**
In `prompts.py`, the SYSTEM_PROMPT uses `=== P0_GLOBAL_FACTUAL_RULES ===` etc. GPT-5.2 parses XML tags better.
- Replace all `=== SECTION_NAME ===` patterns with XML tags: `<section_name>` / `</section_name>`.
- Specific replacements:
  - `=== P0_GLOBAL_FACTUAL_RULES ===` → `<p0_global_factual_rules>` ... `</p0_global_factual_rules>`
  - `=== P0_FIELD_ISOLATION_RULES ===` → `<p0_field_isolation_rules>` ... `</p0_field_isolation_rules>`
  - `=== P1_GOOGLE_BING_FEED_RULES ===` → `<p1_google_bing_feed_rules>` ... `</p1_google_bing_feed_rules>`
  - `=== P1_SHOPIFY_CONVERSION_RULES ===` → `<p1_shopify_conversion_rules>` ... `</p1_shopify_conversion_rules>`
  - `=== P2_STYLE_GUIDANCE ===` → `<p2_style_guidance>` ... `</p2_style_guidance>`
- Each section's content stays identical — only the delimiters change.
- Also convert the `=== VARIANT CONTEXT ===` in FINISH_CONTEXT_TEMPLATE to `<variant_context>` / `</variant_context>`.
- Keep the `INSTRUCTION PRIORITY:` block at the top (before first section tag) as plain text since it's a meta-instruction about section ordering.
- Do NOT change any content within sections — only replace the === delimiter lines with XML open/close tags.
