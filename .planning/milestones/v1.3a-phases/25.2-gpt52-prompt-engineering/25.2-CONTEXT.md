<decisions>
## Implementation Decisions

### Generation Architecture
- Separate API calls per platform: Google (variant-level), Bing (variant-level), Shopify (master-SKU, finish-agnostic)
- Separate JSON schemas per platform (use GPT-5.2 strict json_schema mode)
- 3 calls for ALL SKUs — quality is the priority, no cost shortcuts
- Calls run per master SKU: 3 platform calls + finish sentence generation = content for all 28 variants

### Skill Integration
- **Research required before implementation** — do NOT assume skills need to be distilled or abandoned
- Agent Skills (agentskills.io) are designed to be universal across LLMs including GPT-5.2. If they're not working, the implementation is wrong, not the format
- Research must answer: Are we passing skills correctly? Should GPT-5.2 be set up as an agent with skill capabilities? Are skills right-sized per spec (< 5000 tokens recommended)?
- Test BOTH format effectiveness (does SKILL.md format help GPT-5.2?) AND content relevance (which skill knowledge matters per platform?)
- Check agentskills.io spec for GPT-5.2 integration guidance, OpenAI docs for system prompt best practices, AND run empirical tests
- Load only platform-relevant skills per call (not all 8 simultaneously — that's the current broken pattern)

### {FINISH_SENTENCE} Mechanism
- Finish sentences are generated PER PRODUCT (not generic) — 28 product-specific sentences accounting for finish-product pairing, collection context, and buyer appeal
- `{FINISH_NAME}` in titles: straight name swap (e.g., "Satin Brass"), no product-specific variation
- `{FINISH_SENTENCE}` in descriptions: GPT-5.2 places the placeholder where it flows naturally (not a fixed position)
- Variant expansion swaps placeholders with real finish names and finish sentences
- This avoids 28x API calls per SKU — one master generation + finish sentences = all variants

### Evidence Handling
- **Do NOT band-aid with word banning** — the banned word list treats symptoms, not root causes
- Research the underlying problem: Bobby's hypothesis is it's a prompt/skill issue, not a data quality issue
- A properly instructed model with correctly loaded skills should understand Allied Brass's brand deeply enough to avoid generic language, competitor references, and manufacturer copy echoing
- Pass ALL evidence data — the model should use its judgment about what's relevant
- Fix the skill/prompt problem first, then assess if any data quality issues remain
- Key principle: never address a symptom without resolving the underlying cause

### Claude's Discretion
- Parallel vs sequential platform calls (whichever produces better results)
- Whether finish sentences are generated in the same call or a separate focused call (research decides)
- Specific API parameters (reasoning_effort level, max_completion_tokens, etc.) based on OpenAI docs research

</decisions>

<specifics>
## Specific Ideas

- "The problem isn't 'compress 267K into 18K' — it's 'what does GPT-5.2 need to produce perfect output for one product on one platform?'"
- Skills contain valuable domain knowledge that SHOULD specialize GPT-5.2 — the question is whether we're using the skill format correctly, not whether to abandon it
- Finish sentences exist because specific finishes pair better with certain products and collections — Polished Brass on a Waverly Place towel bar needs a completely different sentence than Matte Black on a Continental soap dish
- Evidence echoing (banned words, bad grammar, competitor names) is likely caused by GPT-5.2 not understanding the brand deeply enough, not by the evidence data itself
