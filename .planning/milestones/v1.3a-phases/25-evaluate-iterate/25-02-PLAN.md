**Step 2: Quality scoring**

For each of the 10 SKUs, use the 10-criterion rubric from Phase 23 to compute a quality score for the NEW description. The rubric weights:
- hook_quality (15%), product_specificity (15%), competitive_diff (12%), keyword_integration (10%)
- customer_scenario (10%), emotional_resonance (10%), factual_accuracy (10%)
- platform_compliance (8%), finish_integration (5%), variety_score (5%)

Score each criterion 0-10. Compute weighted average. Report per-SKU and average across all 10.

**Step 3: Evaluate pass/fail**

Check against success criteria:
- EVAL-03: At least 8/10 new descriptions rated "significantly better" (= won the blind comparison)
- EVAL-04: At least 8/10 pass differentiation test
- EVAL-05: Average quality score >= 85%

**If ALL three pass:** Write final results, declare success, proceed to Plan 25-03.

**If ANY fail — ITERATION REQUIRED:**

For each failing SKU:
1. **Root cause analysis** (MANDATORY before any prompt change):
   - Read the old and new descriptions side by side
   - Identify the SYSTEMIC issue — what instruction disconnect caused the failure?
   - Document: "The prompt says X, but the model produces Y because Z"
   - This is NOT about one SKU — it's about what instruction set change would fix ALL similar failures

2. **Propose holistic prompt fix:**
   - Never patch for one SKU. Fix the instruction set so it works across all 2,800 SKUs.
   - Identify which file(s) need changes (prompts.py, prompt_builder.py, shopping_intelligence.yaml, or skill configs)
   - Document the proposed change and rationale

3. **Apply fix and re-generate ALL 10 SKUs:**
   - Make the prompt change
   - Push to Cloud Run (same deploy flow as Plan 25-01 Task 1)
   - Regenerate all 10 SKUs (not just the failing ones — prevents regression)
   - Update the comparison document with new content
   - Request human re-evaluation (return to Task 1 checkpoint pattern)

4. **Iterate until pass or diminishing returns:**
   - Track each iteration round in the results document
   - If after 3 rounds scores plateau below thresholds, document why and recommend next steps
   - Each round adds a section to the results document

- Prompt files are the ONLY files that should change during iteration. No dashboard, no schema, no infrastructure.
