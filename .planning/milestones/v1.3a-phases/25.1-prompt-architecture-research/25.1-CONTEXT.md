# Phase 25.1: Prompt Architecture Research - Context

**Gathered:** 2026-02-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Investigate why GPT-5.2 produces keyword-stuffed, monotonous, filler-heavy content despite 3 rounds of iteration on the current prompt architecture. Research GPT-5.2 best practices, audit the assembled prompt for anti-patterns and contradictions, design a completely rethought prompt architecture, and validate with A/B tests before returning to Phase 25 evaluation.

This phase does NOT implement changes to production code. It produces a research report, a rewritten prompt design, and A/B test evidence. Production deployment and formal evaluation happen back in Phase 25.

</domain>

<decisions>
## Implementation Decisions

### Research Structure: Two Parallel Tracks

**Track 1 — Internal Audit (Tight)**
- Dump the FULL assembled prompt GPT-5.2 receives for a real SKU (system message + user message with all 8 skills injected)
- Token count it, map its XML structure, identify contradictions between skills
- Score against GPT-5.2 prompting guide anti-patterns checklist: over-instruction, contradictions, example placement, reasoning budget waste
- The contradiction map between skills is essential — GPT-5.2 guide warns contradictory instructions are MORE damaging with GPT-5

**Track 2 — External Research (Wide)**
- GPT-5.2 ecommerce prompting patterns: how other businesses use GPT-5/5.2 for product content, what prompt architectures work, common anti-patterns
- Competitor listing analysis: what titles/descriptions do competitors with 15-20 placements use? Structure, keyword density, length, patterns
- Academic/industry research: Google Ads algorithm insights, ecommerce content best practices, optimal title/description structures from papers and practitioner research
- Cross-reference all external findings with our internal audit to identify specific improvements

### Prompt Audit Approach
- Primary lens: GPT-5.2 anti-patterns checklist (use prompting guide as scoring rubric)
- Dump full assembled prompt as baseline artifact — this is the "before" state
- Map ALL contradictions between the 8 skills + SYSTEM_PROMPT + prompt_builder logic
- Identify which instructions CAUSE each known problem (keyword stuffing, filler, monotonous structure)

### A/B Prompt Testing
- 3 prompt variations per SKU: current prompt, minimal prompt (strip most skills), optimized prompt (GPT-5.2 best practices applied)
- Test on 3 representative SKUs from the evaluation set (different failure modes: keyword stuffing, filler-heavy, monotony)
- ALSO test on random "unseen" SKUs not in the 10 evaluation set — prevents overfitting the prompt to the test set
- Results included inline in the research doc, not as a separate artifact

### Deliverable Format
- Research findings doc + concrete rewritten prompt architecture, both in phase directory (.planning/phases/25.1-*/)
- The rewritten prompt is a COMPLETE RETHINK — designed from scratch based on research findings, not surgical edits to current architecture
- "If we were starting today knowing what GPT-5.2 needs, how would we structure this?"

### Success Criteria
- A/B tests show clear improvement: no keyword stuffing, varied structure, tighter writing
- Content would confidently win blind eval against Round 3 output — "obviously better," not just "better"
- Content helps answer the placement question — optimized for platform algorithms, not just good writing
- All of Robert's evaluation concerns are addressed (competitor material references, weight capacity, excessive dimensions, product type accuracy, heritage bathroom fixtures, keyword stuffing patterns)
- Mini human review checkpoint: generate 3-5 outputs with new prompt, show Bobby for gut check before declaring research complete
- High confidence from both Bobby and Claude that the prompt is at baseline optimal before moving to evaluation

### After Research: Return to Phase 25
- Re-run full evaluation (Round 4) with the new prompt architecture
- All 10 SKUs regenerated, proper blind evaluation with Robert
- The research gives confidence, but Robert's formal sign-off is required before publishing

### Claude's Discretion
- Which 3 representative SKUs to use for A/B testing
- Which random "unseen" SKUs to include for generalization testing
- Specific GPT-5.2 anti-pattern scoring methodology
- How to structure the research doc internally
- Whether to use metaprompting (GPT-5.2 guide mentions it) as part of the optimization approach

</decisions>
