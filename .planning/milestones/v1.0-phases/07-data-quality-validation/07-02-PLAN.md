**Create `src/feedops/jobs/multi_sku.py`** (VALID-03, VALID-08):

1. `detect_multi_sku_families(master_skus: list[str]) -> dict[str, list[str]]`
   - Query variant_index for shopify_product_id of given master_skus
   - Group by shopify_product_id, find product_ids with >1 distinct master_sku
   - Return dict mapping each affected master_sku to its family members
   - Example: `{"DMF-2/2X": ["DMF-2/2X", "DMF-2/3X", "DMF-2/4X"]}`
   - Use a single SQL query via supabase RPC or execute_sql for efficiency:
     ```sql
     SELECT vi1.master_sku, vi2.master_sku as sibling_sku
     FROM variant_index vi1
     JOIN variant_index vi2 ON vi1.shopify_product_id = vi2.shopify_product_id
     WHERE vi1.master_sku IN ({batch_skus})
       AND vi1.master_sku != vi2.master_sku
       AND vi1.shopify_product_id IS NOT NULL
     ```
   - Since supabase postgrest doesn't support self-joins, use `get_client()` then execute raw SQL via supabase RPC or use two queries: (1) get product_ids for batch, (2) get all master_skus for those product_ids

2. `is_multi_sku_family(master_sku: str) -> bool`
   - Quick check for single SKU: query variant_index for its shopify_product_id, then count distinct master_skus with same product_id
   - Return True if count > 1

3. `get_family_metadata(master_sku: str, family_members: list[str]) -> dict`
   - Return metadata dict suitable for storing alongside performance records:
     ```python
     {
         "is_multi_sku_family": True,
         "family_members": ["DMF-2/2X", "DMF-2/3X", "DMF-2/4X"],
         "family_size": 3,
         "data_aggregation": "product_id_level"
     }
     ```

**Create `src/feedops/jobs/contamination.py`** (VALID-04, VALID-09):

1. `check_baseline_eligibility(master_sku: str, platform: str = "google") -> tuple[bool, str]`
   - Query publish_events for the master_sku + platform where published_at > (now - 30 days) AND status = 'success'
   - If recent publish exists: return (False, f"Published {days_ago} days ago (< 30 day threshold)")
   - If no recent publish: return (True, "Eligible for baseline capture")
   - Use VALIDATION_THRESHOLDS["baseline_contamination_days"] = 30 from validators.py (add this threshold)

2. `check_batch_eligibility(master_skus: list[str], platform: str = "google") -> dict[str, tuple[bool, str]]`
   - Batch version: single query for all SKUs, returns dict of sku -> (eligible, reason)
   - Query: `SELECT DISTINCT master_sku, published_at FROM publish_events WHERE master_sku IN (...) AND platform = ... AND status = 'success' AND published_at > threshold ORDER BY published_at DESC`
   - For each SKU with a recent publish, mark ineligible
   - For SKUs not in results, mark eligible

3. `validate_date_boundaries(baseline_start: str, baseline_end: str, master_sku: str, platform: str) -> tuple[bool, str]`
   - Check if the baseline capture date range overlaps with any publish event for this SKU
   - Query: publish_events where published_at BETWEEN baseline_start AND baseline_end AND status = 'success'
   - If overlap: return (False, f"Baseline period overlaps publish event at {published_at}")
   - If clean: return (True, "No publish events in baseline period")
