- IMPORTANT: Relax the `min_length=1` constraint on `skus` field in StartBackfillRequest when mode is incremental — change to `min_length=0` and validate manually (raise 400 if skus empty AND mode is not incremental)

**Function 1: send_slack_notification(message: str, channel: str | None = None) -> bool**
- Read SLACK_WEBHOOK_URL from environment (os.environ.get)
- If not set, log warning and return False (graceful degradation)
- POST to webhook URL with `{"text": message}` using `httpx` (already in project deps) or `urllib.request` (stdlib)

- Read RESEND_API_KEY from environment
- Read ALERT_EMAIL_TO from environment (default recipient)
- If neither API key nor to_email configured, log warning and return False
- POST to `https://api.resend.com/emails` with:
  ```json
  {"from": "FeedOps <alerts@feedops.allied-brass.com>", "to": [to_email], "subject": subject, "text": body}
  ```
- Use urllib.request (no new dependency)
- Return True on success, False on failure
- Timeout: 10 seconds

**Function 3: notify_job_event(event_type: str, job_id: str, job_type: str, details: dict | None = None) -> None**
- High-level helper that formats and sends notifications based on event type
- event_type: "started", "completed", "failed"

- For "failed": Send BOTH Slack AND email — message includes error details from `details` dict
- Call send_slack_notification and/or send_email_alert as appropriate
