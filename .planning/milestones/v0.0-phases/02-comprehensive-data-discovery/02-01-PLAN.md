Create a Python script that uses GoogleAdsFieldService to comprehensively enumerate:

**Part A - Views/Resources (DISC-01):**
Query all resources that are relevant to Shopping campaigns. Use the existing `scripts/discover_fields.py` pattern for client loading. Run these GoogleAdsFieldService queries:

1. `SELECT name, category, selectable, filterable, sortable, data_type WHERE name LIKE 'shopping%'` - All shopping resources
2. `SELECT name, category WHERE name LIKE '%_view'` - All view resources
3. `SELECT name, category WHERE name LIKE 'asset_group%'` - PMax asset resources
4. `SELECT name, category WHERE name = 'campaign' OR name = 'ad_group' OR name = 'search_term_view' OR name = 'product_group_view'` - Core campaign resources

For each resource found, query its selectable fields: `SELECT name, data_type, is_repeated, selectable, filterable, sortable WHERE selectable_with = '{resource_name}'`

Capture: resource name, field count, list of selectable fields with types.

**Part B - Performance Metrics (DISC-02):**
Query: `SELECT name, data_type, is_repeated WHERE name LIKE 'metrics.%' AND selectable_with = 'shopping_performance_view'`

Group metrics by category:
- Core performance (impressions, clicks, CTR, cost)
- Conversion metrics (conversions, value, rate, ROAS)
- Shopping cart data (orders, revenue, units_sold, COGS, margin)
- Impression share (search_impression_share, budget/rank lost)
- Cross-sell/lead metrics
- Attribution (cross_device, view_through)

Capture: metric name, data type, whether it returns data for this account (run a test query with each metric group against LAST_7_DAYS).

**Part C - Report Type Mapping (DISC-06):**
For each Shopping-relevant view identified in Part A, document:
- What level of granularity it provides (product, campaign, ad group, query)

  <action>
Using the metrics enumerated in Task 1, run live validation queries against shopping_performance_view to confirm which metric groups actually return data for this account (customer 6253381786).

Run one query per metric group (LAST_7_DAYS, LIMIT 5):

1. **Core performance test:**
```sql
SELECT segments.product_item_id, metrics.impressions, metrics.clicks, metrics.ctr, metrics.cost_micros, metrics.average_cpc
FROM shopping_performance_view WHERE segments.date DURING LAST_7_DAYS AND metrics.impressions > 0 LIMIT 5
```

2. **Conversion metrics test:**
```sql
SELECT segments.product_item_id, metrics.conversions, metrics.conversions_value, metrics.conversions_from_interactions_rate, metrics.conversions_value_per_cost, metrics.cost_per_conversion
FROM shopping_performance_view WHERE segments.date DURING LAST_7_DAYS AND metrics.impressions > 0 LIMIT 5
```

3. **Shopping cart data test:**
```sql
SELECT segments.product_item_id, metrics.orders, metrics.average_order_value_micros, metrics.revenue_micros, metrics.units_sold, metrics.gross_profit_micros
FROM shopping_performance_view WHERE segments.date DURING LAST_7_DAYS AND metrics.impressions > 0 LIMIT 5
```

4. **Impression share test:**
```sql
SELECT campaign.id, metrics.search_impression_share, metrics.search_click_share, metrics.search_budget_lost_impression_share, metrics.search_rank_lost_impression_share
FROM campaign WHERE campaign.advertising_channel_type IN ('SHOPPING', 'PERFORMANCE_MAX') AND segments.date DURING LAST_7_DAYS LIMIT 5
```

5. **Cross-sell/lead test:**
```sql
SELECT segments.product_item_id, metrics.cross_sell_revenue_micros, metrics.cross_sell_units_sold, metrics.lead_revenue_micros
FROM shopping_performance_view WHERE segments.date DURING LAST_7_DAYS AND metrics.impressions > 0 LIMIT 5
```

For each query: record whether it succeeded, how many non-null/non-zero values returned, and sample data. If a query fails, document the error. Add these validation results to the JSON output file under a "metric_validation" key.

This is critical for Phase 3 sample testing -- we need to know which metrics actually have data vs being theoretically available.
