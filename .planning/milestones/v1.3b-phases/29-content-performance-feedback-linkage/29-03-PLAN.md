**API Route 1: `/api/content-impact/[sku]/route.ts`**

GET handler accepting `sku` param and optional `event_id` query param.

**Data returned:**
1. **Publish event details**: master_sku, platform, published_at, prompt_hash, content_version
2. **Baseline metrics**: avg_ctr, avg_cvr, avg_impressions, avg_clicks from performance_baselines
3. **Window metrics**: Same 7/14/30-day aggregation as landing route, but include full detail: individual snapshot data points per day for a time series
4. **Impact scores**: All metric_name rows from performance_impact_scores for this event — includes pre_value, post_value, control_pre, control_post, did_lift_pct, label, confidence, sample sizes
5. **Control cohort info**: Query performance_snapshots where `publish_event_id = event_id AND cohort_type = 'control'` (these are the control SKUs the Python collector selected). Return distinct master_sku values as `control_skus` array with their avg metrics.
6. **Publish history**: For re-published SKUs, return ALL publish events for (master_sku, platform) ordered by published_at DESC, so the UI can show history section

If `event_id` not provided, use the latest publish event for that SKU.

SKU param handling: Use `getSkuCandidates` from `@/lib/sku-utils.ts` to handle URL-encoded SKUs with slashes/hyphens (consistent with existing review pages).

**API Route 2: `/api/content-impact/[sku]/search-terms/route.ts`**

GET handler accepting `sku` param and required `event_id` query param.

**Logic — Reuse existing pattern from `/api/monitoring/search-delta/route.ts`:**
1. Get the publish event's `published_at` date
2. Query `search_query_snapshots` for this master_sku with `snapshot_date` BEFORE published_at (pre-publish snapshot)
3. Query `search_query_snapshots` for this master_sku with `snapshot_date` AFTER published_at (post-publish snapshot, ideally the closest snapshot ~7-14 days post)
4. Compare: For each search term, compute impression delta and click delta
5. Classify each term:
   - **gained**: post impressions > pre impressions (or new term with 0 pre)
   - **lost**: post impressions < pre impressions (or term disappeared)
   - **new**: pre impressions = 0, post impressions > 0 (gets "New" badge in UI)
6. Sort gained by impression_delta DESC, lost by impression_delta ASC
7. Return `{ gained: SearchTermDelta[], lost: SearchTermDelta[], pre_snapshot_date: string, post_snapshot_date: string }`

```typescript
interface SearchTermDelta {
  search_term: string
  pre_impressions: number
  post_impressions: number
  impression_delta: number
  pre_clicks: number
  post_clicks: number
  click_delta: number
  is_new: boolean  // pre_impressions === 0
}
```

Both routes use `createServiceClient()` from `@/lib/supabase/server`.
