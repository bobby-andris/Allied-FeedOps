Create `dashboard/src/app/api/content-impact/route.ts` with a GET handler.

**Data flow:**
1. Query `publish_events` where `status = 'success'` and `action = 'publish'`, ordered by `published_at DESC`. Select: id, master_sku, platform, published_at, prompt_hash, content_version, product_category (if column exists).
2. Extract unique master_skus from events.
3. Query `performance_baselines` for those SKUs. Select: master_sku, platform, avg_ctr, avg_cvr, avg_impressions, avg_clicks.
4. Query `performance_snapshots` for those SKUs. Select: master_sku, platform, snapshot_date, ctr, cvr, impressions, clicks, days_since_publish, publish_event_id.
5. Query `performance_impact_scores` for event IDs. Select: publish_event_id, metric_name, did_lift_pct, label, confidence, sample_size_treated, sample_size_control. Filter metric_name IN ('ctr', 'cvr').
6. Join in application code (not SQL join — consistent with existing codebase pattern).

**Window aggregation logic:**
For each publish event, aggregate snapshots by `publish_event_id`:
- 7-day window: `days_since_publish >= 1 AND days_since_publish <= 7` (exclude day 0 per research pitfall #4)
- 14-day window: `days_since_publish >= 1 AND days_since_publish <= 14`
- 30-day window: `days_since_publish >= 1 AND days_since_publish <= 30`
- For each window: calculate mean CTR, mean CVR, data point count
- If no snapshots in window: return `{ available: false, pending_days: X }` where X = window_size - days elapsed

**Impact score tier classification:**
```typescript
type ImpactTier = 'strong_improvement' | 'moderate_improvement' | 'no_change' | 'moderate_decline' | 'decline' | 'insufficient_data'

function classifyImpact(score: ImpactScore | null): { tier: ImpactTier; label: string; color: string } {
  if (!score || score.sample_size_treated < 7 || score.sample_size_control < 7) {
    return { tier: 'insufficient_data', label: 'Insufficient Data', color: 'gray' }
  }
  const lift = score.did_lift_pct
  if (lift === null) return { tier: 'insufficient_data', label: 'Insufficient Data', color: 'gray' }
  if (lift >= 10) return { tier: 'strong_improvement', label: 'Strong Improvement', color: 'green' }
  if (lift >= 3) return { tier: 'moderate_improvement', label: 'Moderate Improvement', color: 'emerald' }
  if (lift <= -10) return { tier: 'decline', label: 'Decline', color: 'red' }
  if (lift <= -3) return { tier: 'moderate_decline', label: 'Moderate Decline', color: 'orange' }
  return { tier: 'no_change', label: 'No Significant Change', color: 'gray' }
}
```

**Response shape:**
```typescript
interface ContentImpactRow {
  publish_event_id: number
  master_sku: string
  platform: string
  published_at: string
  prompt_hash: string | null
  has_baseline: boolean
  baseline: { avg_ctr: number; avg_cvr: number } | null
  windows: {
    d7: WindowMetrics | null   // null = insufficient data
    d14: WindowMetrics | null
    d30: WindowMetrics | null
  }
  impact: { tier: ImpactTier; label: string; color: string; ctr_lift: number | null; cvr_lift: number | null }
  is_latest_publish: boolean  // for re-published SKUs, only latest = true
}

interface WindowMetrics {
  available: boolean
  avg_ctr?: number
  avg_cvr?: number
  ctr_delta?: number    // post - baseline
  cvr_delta?: number
  data_points?: number
  pending_days?: number // if not yet available
}
```

**Re-published SKU handling (per CONTEXT.md):**
Group events by (master_sku, platform). For each group, mark only the most recent event as `is_latest_publish: true`. Return ALL events but the UI will default to showing latest only.

**Error handling:** Use try/catch, return 500 with `{ error: string }` on failure. Return empty array if no publish events exist.

Use `createServiceClient()` from `@/lib/supabase/server` for authenticated queries.
