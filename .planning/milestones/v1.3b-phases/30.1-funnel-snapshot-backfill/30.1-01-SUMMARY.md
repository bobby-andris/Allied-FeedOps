## Accomplishments

- Ran backfill for 30-day window (2026-01-25 to 2026-02-24) producing 31 distinct snapshot dates and 4,093 total rows
- FunnelTrendCards on Shopping Funnel page now shows real trend arrows with percentage changes (no longer "No prior data")
- 7 unit tests pass covering auth, day loop, row format mapping, and error resilience

**Plan metadata:** (this commit)

## Files Created/Modified
- `dashboard/src/app/api/funnel-snapshots/backfill/route.ts` - Authenticated backfill endpoint accepting `{start_date, end_date}`, iterates day-by-day calling getLabelTierPerformance, upserts to funnel_snapshots_daily
- `dashboard/src/app/api/funnel-snapshots/__tests__/backfill.test.ts` - 7 unit tests for auth, day loop, row format, and error resilience

## Decisions Made
- Used same date for both `startDate` and `endDate` per day — GAQL aggregates across multi-day ranges, so single-day params required for per-day granularity (research pitfall 1)
- Per-day try/catch instead of overall — one failing day does not abort remaining days
- 90-day safety cap prevents runaway API calls

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Auth proxy was blocking /api/funnel-snapshots/backfill**
- **Found during:** Task 2 (run backfill via curl)
- **Issue:** The auth proxy middleware was not whitelisted for the new backfill route, causing 401 responses even with valid CRON_SECRET
- **Fix:** Added `funnel-snapshots/backfill` to the auth proxy whitelist in the same pattern as `funnel-snapshots/capture`
- **Files modified:** (auth proxy config)
- **Verification:** curl backfill returned 200 with valid row counts
- **Committed in:** d3f33ebd
