The module MUST have these functions:

```python
def build_core_prompt(
    parent_sku: ParentSKU,
    evidence: list,  # raw evidence rows for keyword placement
    evidence_markdown: str,
    platform: str,
    content_type: str,
    finish_code: str | None = None,
) -> str:
    """Build rich prompt — identical for batch and single-SKU paths.

    Includes: keyword placement plan, segment strategy, gold examples,
    Shopping intelligence (when PROMPT_CONTRACT_V2 enabled),
    category guidance, finish context.
    """
```

```python
def apply_feedback_layer(
    core_prompt: str,
    corrections: list[dict] | None = None,
    session_feedback: str | None = None,
) -> str:
    """Layer persistent corrections + session feedback on top of core prompt.
    Feedback is additive per CONTEXT.md — enriches the base, doesn't fork it."""
```

**build_core_prompt() construction order (mirrors generator.py enrichments):**

1. **Evidence table** — `evidence_markdown` (already passed in)
2. **Target platform + content type** header
3. **Keyword placement plan** — call `build_keyword_placement_plan(parent_sku, evidence)` then `format_keyword_placement_section(plan)`. If keyword_placement functions raise or return empty, gracefully skip (not all SKUs have keyword data).
4. **Segment strategy guidance** — extract custom_label_0 values from `parent_sku.merchant_center_items`, call `resolve_segment_strategy()` then `format_segment_strategy_guidance()`. Gracefully skip if no segment data.
5. **Shopping intelligence section** — call `get_shopping_intelligence_section(custom_label_0)` from `shopping_intelligence.py` (Plan 01). **Only include when `is_prompt_contract_v2_enabled()` is True** — this is how FIX-02 makes the flag observable.
6. **Category guidance** — from `get_category_guidance()` with `build_category_guidance()` fallback (same as current)
7. **Gold examples** — use `format_gold_standard_examples_bundle(max_examples=2)` if it exists, otherwise fall back to `format_gold_standard_examples(platform, content_type, max_examples=3)`. Check prompt_loader.py for which function is available.
8. **Finish context** — platform-specific finish handling (same as current `_build_generation_user_prompt()`)
9. **JSON output instruction** — same as current

**CRITICAL FIX-02 implementation:**
- `PROMPT_CONTRACT_V2` enabled → Shopping intelligence section is included in prompt. Disabled → omitted.
- `INTENT_CURATOR_V1` effect is already in evidence.py — when disabled, evidence markdown lacks intent curation. This is already observable through the evidence content. Document this in a code comment.
- `SEGMENT_STRATEGY_V1` → when disabled, skip segment strategy guidance section.

**apply_feedback_layer():**
- If `corrections` list (from sku_corrections table, to be created in Plan 04) is non-empty, add "Persistent Corrections (STRONGLY WEIGHTED):" section with each correction.
- If `session_feedback` is non-empty, add "Session Feedback:" section.
- If both empty/None, return core_prompt unchanged.
- Pattern per CONTEXT.md: feedback is additive — append to core prompt, don't fork it.
