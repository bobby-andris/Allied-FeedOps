**Create `/api/funnel/summary` (GET):**

Returns the five funnel stage counts. Use Supabase server client. Queries MUST use `COUNT(DISTINCT master_sku)` — NOT row counts (see Pitfall 1 in RESEARCH.md).

```typescript
// Response shape:
{
  funnel: {
    total_catalog: number,    // COUNT(DISTINCT master_sku) FROM variant_index
    has_generated: number,    // COUNT(DISTINCT master_sku) FROM generated_content
    approved: number,         // COUNT(*) FROM sku_approvals WHERE approval_status = 'approved'
    published: number,        // COUNT(DISTINCT master_sku) FROM publish_events WHERE status='success' AND action='publish'
    confirmed_sample: {       // Placeholder until DIAG-04 runs — null initially
      checked: number,
      matched: number,
      last_run: string | null
    } | null
  },
  generated_at: string  // ISO timestamp for freshness
}
```

Use `.rpc()` or raw SQL via Supabase for the COUNT(DISTINCT) queries since the JS client doesn't natively support DISTINCT counts. Alternative: use separate `.from().select('master_sku')` queries and deduplicate in JS — but this is expensive for variant_index (72K rows). Prefer using Supabase RPC or the approach the existing stats route uses.

Check `docs/database/SCHEMA.md` BEFORE writing queries to verify column names.

For the confirmed_sample stage: read from a simple JSON file `.planning/phases/18-diagnosis-establish-ground-truth/spot-check-results.json` if it exists (Plan 03 will create it). If not, return `null` with a note that spot-check hasn't been run yet.

**Create `/api/funnel/skus` (GET):**

Accepts query params: `?stage=total_catalog|has_generated|approved|published&limit=100&offset=0`

Returns:
```typescript
{
  stage: string,
  skus: Array<{ master_sku: string; detail?: string }>,
  total: number,
  limit: number,
  offset: number
}
```

For each stage:
- `total_catalog`: `SELECT DISTINCT master_sku FROM variant_index ORDER BY master_sku LIMIT $limit OFFSET $offset`
- `has_generated`: `SELECT DISTINCT master_sku FROM generated_content ORDER BY master_sku LIMIT $limit OFFSET $offset`
- `approved`: `SELECT master_sku FROM sku_approvals WHERE approval_status = 'approved' ORDER BY approved_at DESC LIMIT $limit OFFSET $offset`
- `published`: `SELECT DISTINCT master_sku FROM publish_events WHERE status = 'success' AND action = 'publish' ORDER BY master_sku LIMIT $limit OFFSET $offset`

The `detail` field is optional enrichment (e.g., approval date for approved stage, publish date for published stage). Include if natural from the query; skip if it adds complexity.

Validate the `stage` param — return 400 for invalid values.
