## Decisions Made

- `normalize_offer_id()` uses `.lower()` — simple, safe, idempotent on already-lowercase IDs (double-normalization is no-op per RESEARCH.md anti-patterns)
- `to_gmc_format()` uses `.replace("shopify_us_", "shopify_US_")` — targeted transform, idempotent on already-uppercase
- Both functions return the original value unchanged when None or empty string — safe at all call sites
- Unique constraint column order `(gmc_offer_id, platform, environment, snapshot_date)` exactly matches the `on_conflict` parameter Plan 02 will use in dual-write upserts
- Supabase keychain token is in `go-keyring-base64:{base64}` format — must extract after the colon before base64 decoding (Phase 8 summary's method was slightly different)
