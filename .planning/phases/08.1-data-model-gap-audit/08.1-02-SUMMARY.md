# Phase 08.1 Plan 02: Offer ID Normalization Wiring + Variant Snapshot Dual-Write Summary

**One-liner:** All 4 Python data ingestion codepaths now use `normalize_offer_id()` from the shared utility, and `collect_daily_performance_snapshots()` writes variant-level rows to `performance_snapshots_variant` before aggregating to master_sku.

## What Was Built

### Task 1: Offer ID Normalization Across 4 Codepaths

Applied `from feedops.utils.offer_id import normalize_offer_id` to all 4 target files and replaced inline string operations:

| File | Location | Change |
|------|----------|--------|
| `google_ads_performance.py` | `_fetch_chunk_data()` line ~332 | `product_id = normalize_offer_id(product_id)` after reading from API response |
| `google_ads_search_terms.py` | `_preload_variant_cache()` line ~399 | `normalize_offer_id(gmc_offer_id)` replaces `.lower()` as cache key |
| `google_ads_search_terms.py` | `get_variant_info()` line ~426 | `normalize_offer_id(gmc_offer_id)` replaces `.lower()` before lookup |
| `performance_baseline.py` | `_capture_google_baseline()` line ~629 | `offer_id = normalize_offer_id(offer_id)` at start of loop |
| `performance_impact.py` | `offer_to_sku` dict construction | `normalize_offer_id(offer_id)` as dict key |
| `performance_impact.py` | `by_offer.items()` loop | `offer_to_sku.get(normalize_offer_id(offer_id))` |

No offer ID `.lower()` calls remain in any of the 4 files. The remaining `.lower()` calls in these files are on environment variable strings (e.g., `os.getenv("GOOGLE_ADS_API_ENABLED", "").lower()`), which is correct.

### Task 2: Variant-Level Dual-Write to `performance_snapshots_variant`

Added a new code block in `collect_daily_performance_snapshots()` that executes BEFORE the `aggregated_by_sku` dict is built:

```python
# Locked decisions implemented:
# 1. Normalize on ingestion: normalize_offer_id(offer_id) before lookup
# 2. Skip zero-impression rows: if v_impressions == 0: continue
# 3. Write BEFORE aggregation: variant block precedes aggregated_by_sku construction
# 4. Upsert with correct constraint: on_conflict="gmc_offer_id,platform,environment,snapshot_date"
```

The variant snapshot payload includes: `gmc_offer_id`, `master_sku`, `platform`, `environment`, `snapshot_date`, `impressions`, `clicks`, `ctr`, `conversions`, `conversion_value`, `cost`, `roas`, `fetched_at`.

The `on_conflict` columns exactly match the `uq_variant_snapshots_daily` UNIQUE constraint created in migration 043.
