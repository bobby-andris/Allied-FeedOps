<objective>
Fix critical v1 pipeline bug where _extract_content_from_schema_response() discards all generated content.

The v1 path uses simple_schema {"content": "string"} but the extraction function checks for
platform-specific keys (e.g., "google_description") first. Since those keys don't exist in
the {"content": "..."} response, it returns empty string. For descriptions, the empty string
then becomes "{FINISH_SENTENCE}" via normalize_base_description_with_finish_placeholder().

This is a one-line fix + regression test.
</objective>

**Bug location:** `src/feedops/api/main.py` line 460

**Current code (broken):**
```python
def _extract_content_from_schema_response(response, platform, content_type):
    _FIELD_MAP = {
        ("google", "title"): "google_title",
        ("google", "description"): "google_description",
        ("bing", "title"): "bing_title",
        ("bing", "description"): "bing_description",
        ("shopify", "title"): "shopify_title",
        ("shopify", "description"): "shopify_description",
    }
    field_key = _FIELD_MAP.get((platform, content_type))
    if field_key:                                    # ← BUG: always truthy for mapped pairs
        value = response.get(field_key, "")          # ← key not in response, returns ""
        return (value or "").strip()                 # ← returns ""
    # Fallback: legacy "content" key — UNREACHABLE for mapped pairs
    return (response.get("content", "") or "").strip()
```

**Fix:** Change the `if` condition to check if the key actually exists in the response:
```python
    if field_key and field_key in response:
        return (response[field_key] or "").strip()
```

This way, when the v1 simple_schema response has `{"content": "..."}` but no `google_description`,
the function correctly falls through to the `content` key fallback.
