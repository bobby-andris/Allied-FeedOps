## Objective

Activate the GCP Cloud Scheduler job for daily funnel snapshot capture at 6 AM UTC. Adds Slack failure alerting to the capture endpoint so the scheduler runs silently on success and alerts only on failure or zero-row captures.

**Locked decisions:**
- Schedule: 6 AM UTC daily (not 5 AM ET — different timezone, DST-sensitive)
- Retry policy: 2 retries with 5-minute spacing
- Failure-only Slack alerts (no heartbeat on success)
- SLACK_WEBHOOK_URL stored in Vercel env var, NEVER committed to source code

## Context

@dashboard/src/app/api/funnel-snapshots/capture/route.ts — capture endpoint (currently has no Slack alerting)
@scripts/setup-funnel-scheduler.sh — existing setup script (uses 5 AM ET, 3 retries, 60s-300s backoff)

**Implementation rules:**
- Store webhook URL as `process.env.SLACK_WEBHOOK_URL` — NEVER hardcode the URL

- Error message format: `:warning: FunnelCapture FAILED for {yesterday}\nError: {error.message}`

Place the `sendSlackAlert` helper before the `POST` export function.

Update the comment at top of file: change "5 AM ET" to "6 AM UTC".

After adding Slack alerting, the response behavior is unchanged:
- On success: return `{ snapshot_date, rows_captured, rows_deleted }` with 200
- On error: return `{ error: message }` with 500 (AND send Slack alert before returning)
- On zero rows: return `{ snapshot_date, rows_captured: 0, rows_deleted }` with 200 (AND send Slack alert)

Do NOT change the auth check, upsert logic, or 90-day cleanup logic.
