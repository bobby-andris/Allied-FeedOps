## Objective

Re-backfill 30 days of `funnel_snapshots_daily` using the existing backfill endpoint (run against localhost to avoid Vercel timeout). Write `scripts/validate_phase32.py` that runs all 3 Phase 32 success criteria as SQL checks and prints PASS/FAIL for each. This script is the hard gate before Phase 33 begins.

**Locked decisions:**
- Source data from Google Ads API live queries (existing backfill endpoint does this — do NOT reconstruct from DB)
- Skip days with incomplete data — log which dates returned 0 rows, do not interpolate
- Script must be idempotent — upsert on date+custom_label_0+tier key (already in place in backfill/route.ts)
- Run backfill against localhost:3000 (NOT production Vercel) to avoid 60s timeout

## Context

@dashboard/src/app/api/funnel-snapshots/backfill/route.ts — existing backfill endpoint (already handles upsert + per-day error logging)

## Tasks

### Task 1: Human Checkpoint — Run 30-Day Backfill

**Type:** checkpoint:human-action

The backfill endpoint must run against localhost to avoid Vercel function timeout. Each day makes a Google Ads API call (~2-5s), so 30 days takes ~60-150s total — well beyond Vercel's limit.

**Steps:**

1. Start the local dev server:
   ```bash
   cd dashboard && npm run dev
   ```

2. In a separate terminal, run the backfill (requires CRON_SECRET from Task 3 of Plan 32-02):
   ```bash
   # Calculate dates (run in terminal to get actual values)
   START_DATE=$(date -v-30d +%Y-%m-%d)  # macOS
   END_DATE=$(date -v-1d +%Y-%m-%d)     # macOS (yesterday)

   curl -s -X POST http://localhost:3000/api/funnel-snapshots/backfill \
     -H "Authorization: Bearer <your-CRON_SECRET>" \
     -H "Content-Type: application/json" \
     -d "{\"start_date\": \"${START_DATE}\", \"end_date\": \"${END_DATE}\"}" \
     | jq .
   ```

3. Review the output:
   - `total_rows` should be > 0 (expect 30-100 rows per day based on tier × custom_label_0 combinations)
   - Days with `rows: -1` indicate Google Ads had no data or an API error — log these, do not retry automatically
   - Days with `rows: 0` are valid (no activity that day)

4. Verify rows in production Supabase:
   ```sql
   SELECT COUNT(*), MIN(snapshot_date), MAX(snapshot_date)
   FROM funnel_snapshots_daily;
   ```

### Task 2: Write Phase Gate Validation Script

**Type:** auto

<files>
  scripts/validate_phase32.py
</files>

<action>
Create `scripts/validate_phase32.py` — a standalone Python script that validates all 3 Phase 32 success criteria and prints PASS/FAIL for each.

**Script requirements:**
- No external packages beyond `requests` (already available via uv) and standard library
- Reads credentials from environment: `SUPABASE_URL` and `SUPABASE_KEY` (service role key)
- Designed to run after sourcing `.env.vercel`: `set -a && source .env.vercel && set +a && python scripts/validate_phase32.py`
- Each check is independent — one failure does not skip others
- Exits with code 0 if ALL checks pass, exits with code 1 if ANY check fails
- Reusable: adds a `run_check(name, sql, pass_condition)` pattern other phases can copy

**The 3 success criteria to check:**

**Check 1 (OPS-01):** Cloud Scheduler running + funnel_snapshots_daily has rows from last 7 days
```sql
SELECT COUNT(*) as row_count
FROM funnel_snapshots_daily
WHERE snapshot_date >= CURRENT_DATE - INTERVAL '7 days';
```
Pass condition: `row_count > 0`
Note: Cloud Scheduler cannot be directly verified via SQL, but rows from the last 7 days proves it fired (or the backfill + manual trigger covered the window). Print a note about this.

**Check 2 (OPS-03):** query_value_scores has all 4 new columns
```sql
SELECT column_name
FROM information_schema.columns
WHERE table_name = 'query_value_scores'
  AND column_name IN ('tier_fit_scores', 'recommended_tier', 'net_monthly_impact', 'scored_at');
```
Pass condition: exactly 4 rows returned

**Check 3 (OPS-04):** experiment_outcomes has all 3 new columns
```sql
SELECT column_name
FROM information_schema.columns
WHERE table_name = 'experiment_outcomes'
  AND column_name IN ('p_value', 'confidence_interval', 'minimum_sample_size');
```
Pass condition: exactly 3 rows returned
