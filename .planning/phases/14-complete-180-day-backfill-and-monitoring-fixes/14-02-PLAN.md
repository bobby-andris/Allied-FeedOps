  <name>Task 1: Fetch all 2,784 master SKUs and trigger performance backfill</name>
  <files></files>
  <action>
    **Step A — Get pre-backfill baseline:**
    ```sql
    SELECT COUNT(DISTINCT master_sku) AS current_baseline_count FROM performance_baselines;
    ```
    Record this count (expected: ~96). This is the comparison baseline.

    **Step B — Fetch all distinct master SKUs from variant_index:**
    Use Supabase MCP execute_sql (NOT a raw PostgREST fetch — variant_index has ~72k rows):
    ```sql
    SELECT DISTINCT master_sku FROM variant_index ORDER BY master_sku;
    ```
    Collect all distinct master_sku values into a list. Expected: 2,784 distinct values.

    **Step C — Trigger performance_metrics backfill via /backfill/start:**
    ```bash
    curl -s -X POST https://feedops-pipeline-623866089882.us-east1.run.app/backfill/start \
      -H "Content-Type: application/json" \
      -d '{
        "job_type": "performance_metrics",
        "skus": [...all 2784 master_skus...],
        "config": {
          "days_lookback": 180,
          "batch_size": 10
        }
      }'
    ```
    Expected response: `{"job_id": "...", "status": "running", "total_items": 2784, ...}`

    Record the job_id from the response. This is the resume handle.

    Note: The endpoint accepts up to 3000 SKUs (max_length=3000 in StartBackfillRequest). 2,784 is within the limit.

    **Step D — Monitor job progress:**
    Poll the job status every 2 minutes:
    ```bash
    curl -s https://feedops-pipeline-623866089882.us-east1.run.app/backfill/status/{JOB_ID}
    ```
    Monitor `status`, `completed_items`, `failed_items`, `eta_seconds`.

    If status = "failed" or "partial": resume via:
    ```bash
    curl -s -X POST https://feedops-pipeline-623866089882.us-east1.run.app/backfill/resume/{JOB_ID}
    ```
    Resume picks up from checkpoint — no data duplication.

    The job processes 2,784 SKUs in batches of 10 = 279 batches. At ~10 QPS rate limiting, expect 30-90 minutes total runtime.
