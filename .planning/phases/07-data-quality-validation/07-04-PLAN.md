```python
async def get_validation_report(job_id: str | None = None) -> ValidationReportResponse:
    """Get data quality validation report.

    Returns completeness (if job_id provided), freshness, and outlier metrics.
    Dashboard uses this to display data quality indicators.

    Args:
        job_id: Optional job ID for completeness check

    Returns:
        ValidationReportResponse with quality metrics
    """
    from feedops.jobs.quality_report import generate_full_quality_report
    from datetime import datetime, timezone

    report = generate_full_quality_report(job_id=job_id)

    return ValidationReportResponse(
        completeness=report.get("completeness"),
        freshness=report["freshness"],
        outliers=report["outliers"],
        generated_at=datetime.now(timezone.utc).isoformat(),
    )
```

Update `src/feedops/jobs/processor.py` to call `correct_job_status` after setting the final job status. This is the enforcement mechanism for VALID-07.

**Location**: At the end of the `run()` method, AFTER `update_job_status(self.job_id, final_status, ...)` and BEFORE the final logger.info.

**Add these lines**:
```python
# Post-completion validation: correct status if processor's success calculation
# doesn't match the 95% threshold from VALIDATION_THRESHOLDS (VALID-07)
try:
    from feedops.jobs.quality_report import correct_job_status
    correction = correct_job_status(self.job_id)
    if correction["corrected"]:
        final_status = correction["new_status"]
        logger.warning(
            f"Job {self.job_id}: Status corrected from "
            f"'{correction['old_status']}' to '{correction['new_status']}' "
            f"by post-completion validation"
        )
except Exception as e:
    # Don't let validation failure break the processor
    logger.error(f"Job {self.job_id}: Post-completion validation failed: {e}")
```

**Why**: The processor already calculates status at lines 224-236, but it uses a hardcoded 0.95 threshold. By calling `correct_job_status`, we:
1. Use the centralized VALIDATION_THRESHOLDS (single source of truth for the 95% value)
2. Validate against actual DB state (not just in-memory counters)
3. Provide an audit trail via the correction log
4. Satisfy VALID-07 with a verifiable code path from quality_report -> update_job_status

**Import note**: Use lazy import inside the try block (same pattern as other imports in processor.py run() method) to avoid circular imports.
