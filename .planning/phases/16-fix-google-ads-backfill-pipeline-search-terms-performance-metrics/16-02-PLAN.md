# Key code locations

## Search terms client: src/feedops/integrations/google_ads_search_terms.py
- `_fetch_campaign_products` (lines ~462-541): 2-step join — queries shopping_performance_view to map campaign.id → [product_item_id]. Both `days=30` and `start_date`/`end_date` produce identical GAQL syntax.
- `fetch_search_terms` (lines ~570-680): Uses campaign_products to join search_term_view results to offer IDs. Calls `get_variant_info()` for variant_index lookup.
- If `_fetch_campaign_products` returns `{}`, all search terms get `master_sku=None` — job "succeeds" with 0 useful SKU coverage.

## Workers.py bug: src/feedops/jobs/workers.py
- Line 104: `all_terms = client.fetch_search_terms(days=180, limit=10000)` — HARD-CODED days=180, never passes start_date/end_date
- Lines 93-99: `compute_date_range(days_lookback=180)` computes explicit dates but they're only used for `save_search_terms_to_db`, NOT for the fetch call

## Diagnosis candidates (from research, ranked by likelihood)
1. `_fetch_campaign_products` returns 0 results for some date windows
2. `search_term_view` retention limit (~6-8 weeks) makes 180 days impossible
3. Partial date threading bug between _fetch_campaign_products and search_term_view query
4. Workers.py hard-codes days=180 — never uses explicit dates (CONFIRMED code smell)
