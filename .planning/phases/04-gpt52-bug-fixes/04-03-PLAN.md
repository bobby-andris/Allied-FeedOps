Create `scripts/verify_content_quality.py` — a standalone Python script that calls `/optimize-sku` for each test SKU and reports pass/fail per platform based on description length.

**CLI interface:**
```
python scripts/verify_content_quality.py \
    --pipeline-url https://feedops-pipeline-xxx.run.app \
    --master-sku 920D-6 \
    --master-sku AP-41/18
```

**Arguments:**
- `--pipeline-url` (optional): Pipeline base URL. Falls back to `FEEDOPS_PIPELINE_URL` env var. Exits with clear error if neither provided.
- `--master-sku` (optional, repeatable): SKU(s) to verify. Defaults to `["920D-6", "AP-41/18"]` if not provided. (Random SKU from DB deferred — script must work without Supabase access.)
- `--platforms` (optional): Comma-separated platforms. Defaults to `google,bing,shopify`.
- `--min-desc-len` (optional): Minimum description length threshold. Defaults to 500.
- `--timeout` (optional): HTTP timeout in seconds. Defaults to 300 (content generation takes ~3 min).

**Implementation:**

```python
#!/usr/bin/env python3
"""Post-deploy content quality verification script.

Calls /optimize-sku for test SKUs and verifies description length per platform.
Reusable for Phase 5 (Claude provider), Phase 7 (Bing fix), and future prompt changes.

Usage:
    python scripts/verify_content_quality.py --pipeline-url $FEEDOPS_PIPELINE_URL
    python scripts/verify_content_quality.py --pipeline-url $FEEDOPS_PIPELINE_URL --master-sku 920D-6
"""
```

**Core function: `verify_sku(pipeline_url, master_sku, platforms, min_desc_len, timeout)`**
1. POST to `{pipeline_url}/optimize-sku` with JSON body `{"master_sku": master_sku, "content_types": platforms}`
2. Parse JSON response
3. For each platform in the response `results`:
   - Extract `description` field
   - Check `len(description) >= min_desc_len`
   - Record PASS/FAIL with actual char count
4. Return dict of `{platform: {"status": "PASS"|"FAIL", "desc_len": N, "title_preview": first_60_chars}}`

**Output format (printed to stdout):**
```
=== Verification: 920D-6 ===
  google:  PASS (desc: 723 chars) | Title: "Polished Chrome 6 Inch ..."
  bing:    PASS (desc: 651 chars) | Title: "Polished Chrome 6 Inch ..."
  shopify: PASS (desc: 812 chars) | Title: "920D-6 | Allied Brass ..."

=== Verification: AP-41/18 ===
  google:  PASS (desc: 588 chars) | Title: "Polished Nickel 18 Inch ..."
  bing:    FAIL (desc: 342 chars) | Title: "Polished Nickel ..."
  shopify: PASS (desc: 701 chars) | Title: "AP-41/18 | Allied Brass ..."

=== SUMMARY ===
Total: 6 checks | PASS: 5 | FAIL: 1
Overall: FAIL
```

**Error handling:**
- HTTP errors: Print error message, mark SKU as ERROR (not FAIL), continue to next SKU
- JSON parse errors: Same — ERROR, continue
- Timeout: Print timeout message, mark as TIMEOUT, continue
- Connection errors: Print connection error, exit with code 2

**Exit codes:**
- 0: All checks passed
- 1: At least one FAIL
- 2: Connection/setup error (bad URL, no network)

**IMPORTANT:**
- Use `urllib.request` and `urllib.error` (stdlib only — no `requests` dependency needed)
- Follow the pattern from `scripts/smoke_regenerate_lineage.py` for HTTP handling
- Make the script chmod +x with the shebang line
- Do NOT import anything from the feedops package — this is a standalone tool
