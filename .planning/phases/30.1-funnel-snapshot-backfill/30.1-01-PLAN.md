**Create the backfill endpoint** at `dashboard/src/app/api/funnel-snapshots/backfill/route.ts`:

1. Copy the auth pattern exactly from `capture/route.ts` (lines 17-33): check `CRON_SECRET` env var, extract Bearer token from Authorization header, return 401 if missing or mismatched.

2. Parse `{ start_date, end_date }` from request JSON body. Return 400 if either is missing.

3. Add safety: calculate day count between start and end. If > 90, return 400 with message `"Max 90 days per request"`.

4. Iterate day-by-day from start_date to end_date (inclusive). For each day:
   - Call `getLabelTierPerformance({ startDate: dateStr, endDate: dateStr })` — MUST use same date for both params (GAQL aggregates across multi-day ranges, see research Pitfall 1)
   - Map `result.rows` to Supabase rows using the EXACT same mapping as capture/route.ts lines 52-60: `{ snapshot_date, custom_label_0, tier, impressions, clicks, cost_micros, conversions, conversions_value, roas }`
   - Upsert with `{ onConflict: 'snapshot_date,custom_label_0,tier' }` — same as capture/route.ts line 70
   - Log progress: `[backfill] ${dateStr}: ${rows.length} rows`
   - Track results in array: `{ date: string, rows: number }` (use -1 for errors)

5. Return JSON: `{ total_days, total_rows, days: [...] }`

6. Wrap the loop in try/catch per day (not overall) so one failing day does not abort remaining days.

Mock `getLabelTierPerformance` from `@/lib/shopping-funnel/service` and `createAdminClient` from `@/lib/supabase/admin`.

Tests:

- Returns 401 when token does not match CRON_SECRET
- Returns 400 when start_date or end_date missing from body
- Returns 400 when date range exceeds 90 days

- Maps rows to correct format (mock getLabelTierPerformance to return sample rows, verify upsert called with correct column names)
- Continues processing remaining days when one day throws an error (mock first call to throw, verify second call still happens)

Use the same vitest + NextRequest mock pattern as existing tests in the dashboard (check `dashboard/src/app/api/funnel-snapshots/__tests__/` for capture.test.ts if it exists, otherwise use standard vitest mocking patterns from the codebase).
