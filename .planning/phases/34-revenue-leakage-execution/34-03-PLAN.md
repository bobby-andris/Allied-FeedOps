## Goal
Build all the UI components for the Revenue Leakage tab: the hero number with range + confidence dot, ROAS distribution box plots, the flat term list with inline approve/reject + optimistic updates, reason code badges, and the sticky batch approve bar. These components consume data from `useTierScoring` and interaction state from `useRecommendations`.

## Context
- CONTEXT.md locked decisions define exact interaction patterns (no modals, optimistic updates, sticky batch bar).
- Reuse existing components: `TierMovementArrow`, `ImpactBadge`, `ConfidenceBadge`, `formatDollars`.
- `useRecommendations` hook from 34-02 provides `approve()`, `reject()`, `undo()`, `batchApprove()`, `getStatus()`.
- `classifyAllTerms` from 34-02 provides classified terms with reason codes.
- Box plots use Recharts (already installed) with custom bar rendering — no native box plot support.
- The Revenue Leakage tab shows ONLY `pending` and `rejected` terms (accepted terms move to Action Queue).

**RoasBoxPlot.tsx** — ROAS distribution box plots:
```typescript
interface RoasBoxPlotProps {
  distributions: Record<string, GroupDistributions>
}
```
- Build using Recharts `BarChart` with custom shape rendering:
  - Each tier (HIGH, MEDIUM, LOW) is a bar group
  - Bar represents IQR: bottom at p25, top at p75
  - Horizontal line at p50 (median)
  - Whisker dots at min and max (using Recharts Scatter or custom shapes)
- Aggregate across all product groups (average the p25/p50/p75 per tier)
- Color bars: HIGH = green-500, MEDIUM = blue-500, LOW = amber-500
- Overlap zones: where HIGH p25 < MEDIUM p75 or MEDIUM p25 < LOW p75, show a subtle background highlight
- Width: full width of container, height ~200px
- Responsive: labels below bars
- If data is insufficient for any tier, show "No data" text for that bar

The executor should reference `dashboard/src/app/(dashboard)/tier-scoring/components/DistributionChart.tsx` for Recharts patterns used in this project. The box plot is a NEW visualization, not a modification of DistributionChart.

Simpler alternative if custom Recharts shapes prove too complex: Use a pure CSS/HTML box plot with `div` bars positioned by percentage. This avoids Recharts complexity while still showing the same data. The executor should choose whichever approach they can implement correctly.

<task id="34-03-02" title="Build LeakageTermList, LeakageTermRow, and BatchApproveBar" autonomous="true">
### What

**LeakageTermRow.tsx** — Single term row with inline approve/reject:
```typescript
interface LeakageTermRowProps {
  term: ClassifiedTerm  // from reason-codes.ts
  rank: number
  status: RecommendationStatus | null
  onApprove: (term: TermScore) => void
  onReject: (term: TermScore, reason?: string) => void
  onUndo: (searchTerm: string, customLabel0: string) => void
  onViewDetails: (term: TermScore) => void
}
```

Layout (similar to ActionQueueRow but with action buttons):
```
[#rank] [search term] [ConfidenceBadge] [ReasonBadge]
         [verdict text]
         [expandable: ROAS value, current vs recommended tier, peer avg, confidence score]
                                          [TierMovementArrow] [ImpactBadge] [Approve] [Reject]
```

State transitions:
- **Default (pending/null) for `reasonCode !== 'wasted_spend'`**: Show [Approve] (green outline) and [Reject] (red outline) buttons
- **Default (pending/null) for `reasonCode === 'wasted_spend'`**: Show [Block] (red solid, icon: `Ban`) and [Demote] (amber outline, icon: `ArrowDown`) buttons instead of generic Approve/Reject. **Block** calls `onApprove` with `recommendedAction: 'global_block'` (maps to `recommended_action='global_block'` in routing_recommendations). **Demote** calls `onApprove` with `recommendedAction: 'funnel'` and `recommendedTier: 'low'` (standard tier demotion). Both are approve-type actions that move the term to Action Queue.
- **Approved**: Hide action buttons. Show "Approved" / "Blocked" / "Demoted" badge (based on metadata) and [Undo] button (ghost)
- **Rejected**: Hide action buttons. Show "Rejected" badge (red) and [Undo] button. If just rejected, show a text input for optional reason (inline, below the row) with a "Save note" button. Auto-dismiss after 5 seconds or on blur.

**IMPORTANT for LEAK-03**: The `onApprove` callback signature must support an optional `recommendedAction` override:
```typescript
onApprove: (term: TermScore, options?: { recommendedAction?: string; recommendedTier?: string }) => void
```
The `useRecommendations.approve()` method and the API route (34-01) already accept `recommended_action` in the POST body — this just wires the UI to pass `'global_block'` for Block actions. The `recommended_action` check constraint allows: `('global_block', 'competitor', 'branded', 'funnel')`.

The row should be clickable (like ActionQueueRow) to expand/collapse detail section. The approve/reject/undo buttons must `stopPropagation` to avoid triggering row click.

Expandable detail section (collapsed by default):
```
Current ROAS: X.XX | Peer average: Y.YY | Tier fit: current Z.ZZ → recommended Z.ZZ
Confidence breakdown: Data 0.XX • Consistency 0.XX • Significance 0.XX • Intent 0.XX
```

**BatchApproveBar.tsx** — Sticky bar above the term list:

- Button uses `variant="default"` (primary blue/green)
- Show loading state during batch operation (spinner on button, disabled)
- Count should dynamically update as individual approvals happen

### Why
These components implement the core interaction flow — the decision layer where users approve or reject recommendations. The optimistic update pattern from `useRecommendations` hooks into each row.
