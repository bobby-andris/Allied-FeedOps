## Goal
Build the client-side data layer: a `useRecommendations` hook that manages recommendation statuses with optimistic updates, and a reason code classification module that categorizes scored terms into Misplaced, Wasted $, or Under-invested. These are pure logic modules with no UI — consumed by wave 2-3 components.

## Context
- `TermScore` from `tier-scoring.types.ts` already has `isMisplaced`, `impact` (ImpactRange), `confidence`, `tierFitScores`, `currentTier`, `recommendedTier`.
- The API route from 34-01 handles all CRUD. This hook calls that API.
- Under-invested detection (LEAK-04) requires `keyword_metrics` data. For Phase 34, we'll enrich from the API side — the reason code classifier accepts optional keyword data.
- Optimistic updates must revert on API failure (CONTEXT.md locked decision).

## must_haves
- [ ] `useRecommendations` hook loads statuses from API on mount, provides `approve()`, `reject()`, `undo()`, `batchApprove()` functions
- [ ] All mutations use optimistic updates (instant UI state change, background API call, revert on failure)

- [ ] Wasted spend = zero conversions + total_cost_micros > threshold (LEAK-03)

```typescript
import type { TermScore } from '@/lib/optimization/tier-scoring.types'

export type ReasonCode = 'misplaced' | 'wasted_spend' | 'under_invested'

export interface KeywordData {
  avgMonthlySearches: number
}

export interface ClassifiedTerm extends TermScore {
  reasonCode: ReasonCode
  reasonLabel: string // "Misplaced" | "Wasted $" | "Under-invested"
}

// Wasted spend threshold: $5 in cost_micros (5,000,000 micros = $5)
const WASTED_SPEND_THRESHOLD_MICROS = 5_000_000

/**
 * Classify a scored term into a leakage reason category.
 * Priority: wasted_spend > under_invested > misplaced
 */
export function classifyLeakageReason(
  term: TermScore,
  keywordData?: KeywordData
): ReasonCode {
  // Check for wasted spend: zero conversions with meaningful spend
  // Need raw metrics — check if term has zero conversions via impact direction
  // The TermScore doesn't directly expose totalConversions/totalCostMicros.
  // We use the impact.direction === 'downward' as signal for demotion candidates
  // and check metadata if available.
  // For now, use a heuristic: if recommendedTier is significantly lower AND
  // impact direction is downward, it's likely wasted spend.
  // Better: expose these in TermScore or pass as separate param.

  // Under-invested: keyword data shows impression share gap
  if (keywordData?.avgMonthlySearches && term.impact) {
    // If market volume is 2x+ what we're capturing, it's under-invested
    // We don't have raw impressions in TermScore either, so this needs enrichment
    // For Phase 34: if keywordData is provided and term performs well (upward direction),
    // classify as under-invested
    if (term.impact.direction === 'upward' && keywordData.avgMonthlySearches > 0) {
      return 'under_invested'
    }
  }

  // Default: tier mismatch
  return 'misplaced'
}
```

Also export a helper to classify all terms:
```typescript
export function classifyAllTerms(
  terms: TermScore[],
  keywordDataMap?: Map<string, KeywordData>
): ClassifiedTerm[] {
  return terms
    .filter(t => t.isMisplaced)
    .map(t => {
      const reasonCode = classifyLeakageReason(t, keywordDataMap?.get(t.searchTerm))
      return {
        ...t,
        reasonCode,
        reasonLabel: REASON_LABELS[reasonCode],
      }
    })
    .sort((a, b) => (b.impact?.mid ?? 0) - (a.impact?.mid ?? 0))
}
```

```typescript
'use client'

import { useState, useEffect, useCallback, useRef } from 'react'
import type { TermScore, ImpactRange } from '@/lib/optimization/tier-scoring.types'

export type ReviewStatus = 'pending' | 'accepted' | 'rejected' | 'expired'

export interface RecommendationStatus {
  status: ReviewStatus
  updatedAt: string | null
  rejectionReason?: string
}

export interface HistoryEntry {
  search_term: string
  custom_label_0: string
  recommended_tier: string | null
  review_status: ReviewStatus
  accepted_at: string | null
  accepted_by: string | null
  metadata: {
    current_tier?: string
    impact?: ImpactRange
    rejection_reason?: string
    history?: Array<{ action: string; at: string }>
    [key: string]: unknown
  }
  created_at: string
}

interface UseRecommendationsReturn {
  statuses: Record<string, RecommendationStatus> // keyed by "searchTerm::customLabel0"
  history: HistoryEntry[]
  historyLoading: boolean
  approve: (term: TermScore) => Promise<void>
  reject: (term: TermScore, reason?: string) => Promise<void>
  undo: (searchTerm: string, customLabel0: string) => Promise<void>
  batchApprove: (terms: TermScore[]) => Promise<void>
  loadHistory: () => Promise<void>
  getStatus: (searchTerm: string, customLabel0: string) => RecommendationStatus | null
}
```

The hook:
1. On mount, calls `GET /api/shopping-funnel/recommendations?action=statuses` to load current statuses
2. Stores statuses in a `Record<string, RecommendationStatus>` keyed by `${searchTerm}::${customLabel0}`
3. `approve(term)` — optimistic update to 'accepted', then POST to API. Revert on error. Show console.error on failure (toast is UI concern, not hook concern).
4. `reject(term, reason?)` — optimistic update to 'rejected', then POST. Revert on error.
5. `undo(searchTerm, customLabel0)` — optimistic update to 'pending', then POST. Revert on error.
6. `batchApprove(terms)` — optimistic update all to 'accepted', single POST with `action: 'batch_approve'`. Revert all on error.
7. `loadHistory()` — calls `GET /api/shopping-funnel/recommendations?action=history`, stores in `history` state.
8. `getStatus(searchTerm, customLabel0)` — lookup helper that returns the status or null.

Key implementation detail for optimistic updates:
```typescript
async function approve(term: TermScore) {
  const key = `${term.searchTerm}::${term.customLabel0}`
  const previous = statuses[key]

  // Optimistic update
  setStatuses(prev => ({
    ...prev,
    [key]: { status: 'accepted', updatedAt: new Date().toISOString() }
  }))

  try {
    const res = await fetch('/api/shopping-funnel/recommendations', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        action: 'approve',
        searchTerm: term.searchTerm,
        customLabel0: term.customLabel0,
        recommendedTier: term.recommendedTier,
        currentTier: term.currentTier,
        confidence: term.confidence.score,
        impact: term.impact,
      })
    })
    if (!res.ok) throw new Error(`API error: ${res.status}`)
  } catch (err) {
    // Revert
    setStatuses(prev => ({
      ...prev,
      [key]: previous ?? { status: 'pending', updatedAt: null }
    }))
    console.error('Failed to approve recommendation:', err)
  }
}
```

### Why
The hook encapsulates all recommendation state management and API communication. Components just call `approve(term)` and get instant UI feedback.
