# Phase 33.1: Scoring Calibration Investigation

## Problem Statement

Phase 33 built a working tier scoring engine, but real data reveals two critical calibration issues:

1. **95% of terms flagged as "misplaced"** (4,064 of 4,260) — when nearly everything is flagged, nothing is flagged. The scoring is too sensitive or the comparison baseline is wrong.

2. **$0/mo estimated impact** — `estimateImpact()` returns zero for all terms, meaning either CVR deltas between tiers are negligible/negative, or the calculation has a logic error.

## Critical Context: How Tiers Were Assigned

**The current tier assignments (HIGH/MEDIUM/LOW per custom_label_0) were manually assigned by Robert (business owner) based on gut feeling and product knowledge — NOT based on historical performance data.**

This means:
- Robert looked at each custom_label_0 group and each search term
- He assigned HIGH/MEDIUM/LOW based on what he *thought* the intent level should be
- He did NOT look at ROAS, CVR, or any historical metrics when making these assignments
- The scoring engine is comparing statistical performance against human intuition

### Implications

- "95% misplaced" may actually mean "the data shows different patterns than gut intuition predicted" — which is valuable information, not an error
- The scoring engine ISN'T wrong — it's doing exactly what it was built to do (compare actual performance to tier placement)
- But the UI framing of "misplaced" implies something is broken, when really it's showing the gap between intuition and data
- The $0 impact issue is separate and likely a real bug in estimateImpact()

## Investigation Areas

### 1. Impact Estimation Bug ($0 impact)
- Trace `estimateImpact()` with real data for a known high-traffic term
- Check if CVR deltas are actually zero or if there's a calculation error
- Check if impression volumes are being passed correctly
- Verify the $85 AOV assumption is reasonable

### 2. Scoring Sensitivity (95% misplaced)
- Pull actual distribution data for 2-3 groups (e.g., "towel shelves", "shower door knobs")
- Look at the ROAS distributions per tier — are they well-separated or overlapping?
- Check if the z-score threshold for "misplaced" is too aggressive
- Consider: should "recommended tier" require a MINIMUM fit score delta to trigger "misplaced"?

### 3. Reframing the UX Language
- "Misplaced" implies error — but for gut-assigned tiers, "data suggests different placement" is more accurate
- Consider: "Data-aligned" vs "Intuition-aligned" framing
- Hero callout should say something like: "23 terms where data strongly disagrees with current placement — $X/mo opportunity if adjusted"

### 4. Threshold Calibration
- What percentage of terms being flagged is actually useful? (10-20% = actionable, 95% = noise)
- Consider adding a minimum confidence threshold before flagging
- Consider adding a minimum impact threshold ($X/mo) before flagging
- Consider requiring fit score delta > 0.3 (not just "different tier has higher score")

## Expected Outputs

- Root cause of $0 impact bug identified and fixed
- Scoring thresholds calibrated to produce actionable (10-20%) misplaced rate
- Updated hero callout and framing language
- Documentation of calibration decisions for future reference
