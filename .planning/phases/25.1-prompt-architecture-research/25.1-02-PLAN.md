  <action>
Write the actual prompts that will be used in A/B testing:

**new-system-prompt.txt** — The complete new system prompt following CTCO framework:

1. `<context>` section (~500 chars): Who you are, what Allied Brass is, what you're generating
2. `<task>` section (~300 chars): Generate optimized titles and descriptions for the given SKU using ONLY evidence data
3. `<constraints>` section (~8-10K chars): Hierarchical constraints organized by priority:
   - P0 Accuracy: Evidence-only claims, prohibited fabrications, banned content (distilled from current accuracy_guardrail + evaluation feedback)
   - P1 Content Rules: Description structure (first 160 chars = hook, 160-500 = substance, 500-900 = synonyms), title formula (Robert's: finish first, collection + "Collection", product type, dimension only when varies, "Allied Brass" last), length targets (700-900 chars Google/Bing descriptions, 60-150 chars titles)
   - P2 Voice: Brand voice distilled from brand_voice.yaml (confident, specific, concrete; banned words/phrases; positive brass framing without competitor contrast)
   - P3 Platform: Google/Bing/Shopify format differences, field isolation, HTML rules for Shopify
4. `<output>` section (~500 chars): JSON schema reference, claims array requirement, self_score (simplified per architecture doc recommendation)

**Critical rules for writing the new prompt:**
- ZERO contradictions. Before writing each constraint, check it doesn't conflict with any other.
- No SKILL.md content verbatim. Distill essential knowledge only.
- No Claude Code metadata, skill identity, agent guidance, or rule file references.
- Use concrete examples where helpful (e.g., good title example, bad title example) — embed directly, don't reference external files.
- Every prohibition from human evaluation feedback (weight capacity, detailed dimensions, competitor materials, keyword lists, "heritage bathroom fixtures", finish counts) MUST appear exactly once in P0.
- Total system prompt MUST be under 15K characters.

**new-user-prompt-template.txt** — The new user prompt template:
- Use XML tags for structure (matching current pattern in prompts.py)
- Include placeholders: {master_sku}, {evidence_table}, {keyword_placement}, {category_guidance}, {product_design_story}, {competitive_positioning}, {gold_examples}, {finish_context} (optional), {schema}
- Remove segment_strategy_guidance (absorbed into system prompt)
- Move gold_examples to system prompt if architecture doc recommends it (update template accordingly)
- Keep it lean — the user prompt should be evidence + SKU-specific data only

Measure the character count of the new system prompt and document it at the top of the file.
