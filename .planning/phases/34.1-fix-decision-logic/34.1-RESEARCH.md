# Phase 34.1: Fix Decision Logic - Research

**Researched:** 2026-02-25
**Domain:** Tier Intelligence scoring engine, waterfall shopping structure, decision logic
**Confidence:** HIGH

## Summary

Phase 34.1 addresses a critical production issue where the Tier Intelligence dashboard produces backwards recommendations — 154/155 flagged terms show $0 impact and recommend moving zero-ROAS terms to LOW (aggressive bidding). The root cause is a descriptive scoring engine that answers "which tier's distribution do you resemble?" instead of the prescriptive question "what bidding treatment does this term need?"

The fix involves reframing the scoring output from `isMisplaced`/`recommendedTier` to action-oriented `promote`/`constrain`/`block`/`observe`, fixing the impact formula to use term-actual ROAS instead of tier-distribution ROAS, fixing under-invested detection, inverting CPC in fit scoring, unifying the two parallel scoring systems, and adding new capabilities (custom_label_0 blocking, search promotion candidates, label profitability).

**Primary recommendation:** Fix bugs in strict dependency order (types first, then scoring engine, then UI), because every downstream component depends on `TermScore` shape. The action-oriented reframe is the highest-leverage change — it makes wasted-spend-to-LOW impossible by construction.

## User Constraints (from CONTEXT.md)

### Locked Decisions
- **Reframe scoring from descriptive to prescriptive**: Replace `isMisplaced`/`recommendedTier` with action-oriented output: `promote`/`constrain`/`block`/`observe`. The engine should answer "what bidding treatment does this term need?" not "which tier's stats match?"
- **Wasted spend override**: When `reasonCode = wasted_spend`, force action to `constrain` (push to HIGH) or `block`. NEVER recommend LOW for zero-ROAS terms.
- **Fix under_invested detection**: Compare `avgMonthlySearches` against actual impressions, not a boolean (current code evaluates to `> 2` for all terms)
- **Fix ROAS recommendation engine**: Compare observed ROAS against tier's expected distribution, not against bid target (bid target != expected ROAS in waterfall)
- **Invert CPC in fit scoring**: Lower CPC = better fit for any tier. Use signed z-score, not absolute value.
- **Unify scoring systems**: Deprecate `estimateTierFromMetrics()` hardcoded thresholds in `query-intelligence.ts`. Route recommendations API through distribution-based scorer.
- **Fix impact formula**: For wasted spend, impact = cost saved by blocking/constraining. For misplaced terms, use term's actual ROAS vs target tier's expected ROAS.
- **Fix "Constrain" button no-op**: If term already in HIGH, show only Block/Accept (not Constrain)
- **Fix verdict text**: Prescriptive language ("spent $X with zero conversions — block") not descriptive ("fits LOW distribution")
- **Custom label 0 level blocking**: Block ALL terms under a product category at once. UI button on GroupOverview component. Extend `routing_recommendations` table with `action_scope = 'label'`.
- **Search promotion candidates**: Populate `search_buildout_recommendations` table with high-ROAS, high-volume terms. Candidate identification only — no automated keyword creation.
- **Label profitability summary**: Aggregate `label_tier_daily_snapshot` by label. Show profitable vs unprofitable categories, tier efficiency gaps, spend concentration.
- Document `routing_recommendations` table in SCHEMA.md
- Document `query_value_scores` table in SCHEMA.md

### Pattern 1: Action-Oriented Scoring (New)
**What:** Replace descriptive `isMisplaced`/`recommendedTier` with prescriptive `recommendedAction`
**When to use:** All term scoring output

```typescript
// New type in tier-scoring.types.ts
export type RecommendedAction = 'promote' | 'constrain' | 'block' | 'observe'

// Updated TermScore fields (additive — keep isMisplaced for backwards compat initially)
export interface TermScore {
  // ... existing fields ...
  recommendedAction: RecommendedAction  // NEW: what to do
  actionReason: string                   // NEW: why (replaces verdict for action terms)
  totalImpressions: number               // NEW: needed for under_invested fix
}
```

**Decision logic in scoreTerm():**
```typescript
// After computing tierFitScores and confidence:
function determineAction(term, currentTier, termRoas, totalConversions, totalCostMicros): RecommendedAction {
  const costDollars = totalCostMicros / 1_000_000

  // 1. Wasted spend: zero conversions + meaningful spend → block or constrain
  if (totalConversions === 0 && costDollars > 5) {
    return currentTier === 'HIGH' ? 'block' : 'constrain'
    // Already in HIGH (most constrained) → only option is block
    // In MEDIUM/LOW → push to HIGH to constrain
  }

  // 2. High performer in constrained tier → promote (push down funnel)
  if (termRoas > targetTierP75 && currentTier !== 'LOW') {
    return 'promote'
  }

  // 3. Poor performer in aggressive tier → constrain (push up funnel)
  if (termRoas < currentTierP25 && currentTier !== 'HIGH') {
    return 'constrain'
  }

  // 4. Correctly placed
  return 'observe'
}
```

### Pattern 2: Impact Formula Fix
**What:** Use term's actual metrics, not tier-vs-tier distribution comparison
**When to use:** All impact estimation

```typescript
// For wasted spend: impact = money saved
if (recommendedAction === 'block' || recommendedAction === 'constrain') {
  const monthlyCost = totalCostMicros / 1_000_000
  return { low: monthlyCost * 0.5, mid: monthlyCost * 0.8, high: monthlyCost }
}

// For promote/constrain non-wasted: use term ROAS vs target tier expected ROAS
const termRoas = total_conversions_value / (total_cost_micros / 1_000_000)
const targetRoasP50 = targetDist.metrics.roas.p50
const roasDelta = targetRoasP50 - termRoas
const monthlySpend = total_cost_micros / 1_000_000
return { mid: Math.max(0, monthlySpend * roasDelta) }
```

### Anti-Patterns to Avoid
- **Comparing observed ROAS to bid target ROAS:** These are fundamentally different numbers. Bid target is a constraint; observed is a result. The waterfall intentionally produces LOW observed ROAS in HIGH tier (that's working correctly).
- **Using tier distribution fit as action recommendation:** A zero-ROAS term "fitting" LOW's broken distribution is statistically correct but operationally catastrophic. Business logic must override statistical fit.
- **Removing `isMisplaced` abruptly:** Many UI components reference it. Add `recommendedAction` alongside, then migrate consumers gradually.

## Common Pitfalls

### Pitfall 1: Modifying TermScore Without Updating All Consumers
**What goes wrong:** TypeScript build fails across 15+ files referencing TermScore
**Why it happens:** TermScore is used in page.tsx, LeakageTermRow, ActionQueueTable, HistoryView, LeakageTermList, GroupOverview, reason-codes.ts, tier-scoring route, and tests
**How to avoid:** Add new fields as OPTIONAL first (`recommendedAction?: RecommendedAction`), make required only after all consumers updated
**Warning signs:** `npm run build` failures mentioning TermScore property access

### Pitfall 2: Breaking the routing_recommendations Check Constraint
**What goes wrong:** Upsert fails with constraint violation when adding new action types
**Why it happens:** Migration 039 has `recommended_action in ('global_block', 'competitor', 'branded', 'funnel')` — no `'label_block'`
**How to avoid:** Apply ALTER TABLE to add `'label_block'` to the check constraint BEFORE deploying code that writes it
**Warning signs:** 500 errors on POST /api/shopping-funnel/recommendations

### Pitfall 3: Test Fixtures Using Old TermScore Shape
**What goes wrong:** Tests fail because `makeTermScore()` helper doesn't include new required fields
**Why it happens:** Five test files have `makeTermScore()` helpers that need updating
**How to avoid:** Update test fixture helpers first, add new fields with sensible defaults
**Warning signs:** vitest failures in reason-codes.test.ts, tier-scoring.test.ts

### Pitfall 4: Impact $0 Regression
**What goes wrong:** Changing impact formula introduces a different $0 bug
**Why it happens:** The `Math.max(0, ...)` floor combined with negative deltas
**How to avoid:** Write specific tests: wasted spend impact MUST equal spend amount, promote impact MUST be > $0 when ROAS delta is positive
**Warning signs:** Hero callout showing "$0/mo potential impact"

### Pitfall 5: CPC Inversion Breaking Fit Scores
**What goes wrong:** Changing CPC from `Math.abs(zCpc)` to directional inverts recommendations for well-placed terms
**Why it happens:** CPC is 15% of fit score — changing its sign flips fit rankings for terms near CPC boundaries
**How to avoid:** Test with the known production data (HIGH median 1.6x ROAS, MEDIUM 1.9x, LOW 0.3x) to verify the fix doesn't make things worse
**Warning signs:** More terms flagged as misplaced after the fix (expected: fewer)

## Code Examples

### Bug 1 Fix: Wasted Spend Override in scoreTerm()

**Current code** (`tier-scoring.ts:228-231`):
```typescript
// BROKEN: picks "best fit" statistically — 0.0 ROAS "fits" LOW's broken distribution
const recommendedTier = (['HIGH', 'MEDIUM', 'LOW'] as FunnelTier[]).reduce(
  (best, tier) => tierFitScores[tier] > tierFitScores[best] ? tier : best,
  'HIGH' as FunnelTier
)
```

**Fix:** Add action determination after recommendedTier computation:
```typescript
// Determine prescriptive action based on business logic
let recommendedAction: RecommendedAction = 'observe'
const costDollars = term.total_cost_micros / 1_000_000

if (term.total_conversions === 0 && costDollars > 5) {
  // Wasted spend: block if already in HIGH, constrain otherwise
  recommendedAction = currentTier === 'HIGH' ? 'block' : 'constrain'
} else if (isMisplaced && funnelDepth[recommendedTier] > funnelDepth[currentTier]) {
  recommendedAction = 'promote'  // push down funnel for aggressive bidding
} else if (isMisplaced && funnelDepth[recommendedTier] < funnelDepth[currentTier]) {
  recommendedAction = 'constrain'  // push up funnel to restrict bidding
}
```

### Bug 3 Fix: Impact Formula for Wasted Spend

**Current code** (`tier-scoring.ts:355-392`):
```typescript
// BROKEN: uses tier distribution ROAS comparison — LOW p25 < HIGH p50 → negative delta → $0
const lowDelta = targetRoasP25 - currentRoas  // e.g., 0.0 - 1.6 = -1.6 → Math.max(0) = $0
```

**Fix for wasted spend:** Impact = cost saved by blocking
```typescript
if (recommendedAction === 'block' || (recommendedAction === 'constrain' && term.total_conversions === 0)) {
  const monthlyCost = term.total_cost_micros / 1_000_000
  return {
    low: monthlyCost * 0.5,   // conservative: save 50% of spend
    mid: monthlyCost * 0.8,   // expected: save 80% of spend
    high: monthlyCost,        // optimistic: save 100% of spend
    currency: 'USD', period: 'monthly',
    direction: currentTier === 'HIGH' ? 'lateral' : 'upward'
  }
}
```

### Bug 4 Fix: CPC Inversion in Fit Score

**Current code** (`tier-scoring.ts:223`):
```typescript
// BROKEN: treats CPC same as ROAS — but lower CPC is BETTER
const absDeviation = 0.50 * Math.abs(zRoas) + 0.20 * Math.abs(zCvr) + 0.15 * Math.abs(zCpc) + 0.15 * Math.abs(zCtr)
```

**Fix:** For CPC, negative z-score (cheaper than median) should improve fit:
```typescript
// CPC is inverse: lower = better. A negative zCpc means cheaper = better fit.
// Use max(0, zCpc) to only penalize expensive terms, not cheap ones.
const cpcPenalty = Math.max(0, zCpc)
const absDeviation = 0.50 * Math.abs(zRoas) + 0.20 * Math.abs(zCvr) + 0.15 * cpcPenalty + 0.15 * Math.abs(zCtr)
```

## Open Questions

1. **How should `estimateTierFromMetrics` deprecation work?**
   - What we know: `enrichNeedsDecisionTerm()` in `query-intelligence.ts` calls it, which is called by `service.ts` for the NeedsDecision flow. The recommendations GET route uses `buildRecommendationQueue()` which depends on this enrichment.
   - What's unclear: Should the old recommendations GET endpoint be retired entirely, or should it delegate to the distribution-based scorer?
   - Recommendation: Keep `enrichNeedsDecisionTerm()` functional but replace `estimateTierFromMetrics()` internals to use distribution lookup. The recommendations GET endpoint is a separate concern from the tier-scoring endpoint — assess whether it's still used in the UI.

2. **Should `isMisplaced` be removed or kept alongside `recommendedAction`?**
   - What we know: `isMisplaced` is used in page.tsx (`classifyAllTerms` filters on it), GroupOverview, buildHeroCallout, tier-scoring route (totalMisplaced count), and test assertions.
   - Recommendation: Keep `isMisplaced` as a computed property (`recommendedAction !== 'observe'`) for backwards compatibility. This avoids touching every consumer in one shot.

3. **Where does label profitability data come from?**
   - What we know: `label_tier_daily_snapshot` has daily `custom_label_0 + tier` performance data
   - What's unclear: How much historical data exists. The table was backfilled in OPS-02 but that requirement is listed as "Pending."
   - Recommendation: Build the UI with graceful degradation — show "Insufficient data" if < 7 days of snapshots exist.
