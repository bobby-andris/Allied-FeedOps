  <name>Task 1: Enhance /api/performance to support dual time windows and return daysSincePublish</name>
  <files>dashboard/src/app/api/performance/route.ts</files>
  <action>
Extend the existing GET handler to accept two new query params: `baselineWindow` (default `30d`, values `7d|30d|60d`) and `snapshotWindow` (default `30d`, values `7d|30d|60d`).

**Current behavior:** Uses a single `dateRange` param. Fetches live Google Ads data and falls back to `performance_snapshots`. Returns no `daysSincePublish`.

**New behavior:**

1. Parse `baselineWindow` and `snapshotWindow` from search params (alongside existing `platform` and `sku` params). Remove the existing `dateRange` param.

2. For each published SKU, select the latest snapshot from `performance_snapshots` where `snapshot_date` falls within the `snapshotWindow` AFTER the SKU's publish date:
   ```sql
   SELECT * FROM performance_snapshots
   WHERE master_sku = $1 AND platform = $2
     AND snapshot_date >= publish_date
     AND snapshot_date <= publish_date + interval '${snapshotWindowDays} days'
   ORDER BY snapshot_date DESC
   LIMIT 1
   ```
   Use Supabase `.gte()` and `.lte()` filters with JS-computed date strings (format YYYY-MM-DD). Compute `publishDatePlus` = publish_date + snapshotWindowDays.

3. `daysSincePublish`: Read from the matched snapshot record's `days_since_publish` column. If no snapshot found, compute from `publishedAt` to today.

4. Remove the live Google Ads call entirely — this page now reads exclusively from `performance_baselines` + `performance_snapshots`. Add a warning if no snapshots exist: `"No performance snapshots found. Run capture-snapshot to populate data."`.

5. Update `SkuPerformance` interface to add:
   ```typescript
   daysSincePublish: number
   hasSnapshot: boolean
   baselineWindow: string
   snapshotWindow: string
   ```

6. The baseline lookup uses `performance_baselines` table as-is (already keyed by master_sku + platform). The `baselineWindow` param is informational for the UI label; the stored baseline is always the 30-day pre-publish window captured at optimization time. No change to baseline query.

7. Remove all `fetchShoppingPerformance`, `isGoogleAdsConfigured`, `getDateRange`, `ProductPerformance` imports that are no longer used. Keep `createClient` and `NextRequest`/`NextResponse`.

8. Update summary calculation: only include SKUs where `hasSnapshot: true` when computing avg CTR/CVR change. Add `totalWithSnapshot: number` to the summary.

Keep the existing error handling and warning pattern (warnings array, non-fatal errors).
