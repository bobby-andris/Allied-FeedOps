<task type="auto">
  <name>Task 2: Write provider recommendation</name>
  <files>docs/evaluation/recommendation.md</files>
  <action>
Based on the comparison table data, write `docs/evaluation/recommendation.md`:

**Structure:**
1. **Executive Summary** (2-3 sentences): Which model wins overall and why
2. **Default Provider Recommendation**: Single winner for production default, backed by pass rate + cost data
3. **Scenario-Based Exceptions**: Cases where a different provider is better (e.g., "Use Claude Opus for [category] if quality is critical and cost is not a constraint")
4. **Cost/Quality Tradeoff**: Explicit tradeoff analysis — if the cheaper model scores within X% of the expensive one, is the premium worth it?
5. **Implementation Guidance**: What env vars to set for the recommended default. Whether to update factory.py defaults.
6. **Future Evaluation Notes**: What to test next time (prompt optimization for the winning provider, thinking budget tuning for Claude, etc.)

**Decision criteria** (in order of priority):
1. Pass rate (quality is king — 98% approval rate must be maintained)
2. Cost per approved output (effective cost matters more than raw cost)
3. Consistency (production needs predictable output)
4. Latency (matters for UX but secondary to quality)

**If results are close (< 5% pass rate difference):**
- Recommend the cheaper model as default
- Note the premium model as an option for high-value SKUs
- Flag that Claude-optimized prompts (deferred idea) could change the ranking

**If one model clearly wins (> 10% pass rate advantage):**
- Recommend it as default regardless of cost
- Calculate the cost premium and whether it's justified
