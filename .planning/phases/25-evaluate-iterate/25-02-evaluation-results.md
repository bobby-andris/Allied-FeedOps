## Gap-by-Gap Assessment (Round 2)

### Gap 1: Titles include finish — PARTIALLY FIXED

**Evidence:** All 10 new titles now include `{FINISH_NAME}` placeholder. 4/10 new titles won consensus.

**What improved:** Finish name is now structurally present in every new title, which was the #1 reason evaluators chose old titles in Round 1. Titles like `{FINISH_NAME} 6-Inch Solid Brass Towel Ring` are much better than Round 1's finishless titles.

**What still fails:**
- **Finish position:** Robert wants finish name FIRST in title, not buried. Bobby echoed this.
- **Unnecessary dimensions in titles:** Robert: "The only time I would put the dimension in the title is when the product varies by size (i.e. Towel Bars are 18", 24", 30" and 36")." New titles include dimensions for products that don't need them (1020, CL-22).
- **"Solid Brass" placement:** Robert: "I did not like 'Solid Brass' being so close to the beginning of the title. The early part of the title is reserved for the words that will convert best."
- **Missing "Collection" keyword:** Robert: "I would like Skyline to have 'Collection' after the word Skyline." Some titles omit the word "Collection."
- **Style references wanted:** Robert: "We should have style in the title but it should not always be the same title. It should use a variety of style references so that we capture more traffic on google."

### Gap 2: Product-specific differentiation — PARTIALLY FIXED

**Evidence:** 6/10 new descriptions won consensus (same as Round 1's 6/10). Differentiation improved significantly per Robert (10/10) but only modestly per Bobby (5/10).

**What improved:** Descriptions now use product-specific data (manufacturer description, bullets, mounting type) instead of purely generic category framing. The Product Design Story block is feeding real data into prompts.

**What still fails:** The model is still inserting generic competitive claims and filler content instead of focusing on what makes each specific product's DESIGN special. See "New Issues" section below.

### Gap 3: Fluffy vs robotic balance — IMPROVED

**Evidence:** Neither evaluator used the word "fluffy" in Round 2 (Bobby used it 3 times in Round 1). The "manufactured scenario" openers are gone.

**What improved:** Creative direction now anchors on evidence rather than inventing scenarios. Descriptions feel more grounded.

**What still fails:** A new problem emerged: descriptions are now too data-heavy (excessive dimensions, weight capacity, installation details) instead of too fluffy. The pendulum swung from "too creative" to "too technical."

### Gap 4: Factual accuracy — PARTIALLY FIXED

**Evidence:** 1024 still says "Skip the spring-loaded roller" (factual error). 1024 was mislabeled as "Euro Style" (it's a 2-post holder). 1020 was mislabeled as "Towel Hook" (it's a robe hook). Weight capacity of 2 lb stated for 1020 is inaccurate per Robert.

**What improved:** No new fabricated usage scenarios (the "hang it along the tub wall" type errors from Round 1 are gone). The strengthened accuracy guardrail eliminated scenario invention.

**What still fails:** The model still gets product TYPE wrong (Euro Style vs 2-post, Towel Hook vs Robe Hook). These are data accuracy issues — the evidence table may have ambiguous or incorrect product type classifications.

### Gap 5: "28 finishes" on variants — PARTIALLY FIXED

**Evidence:** Several master-level descriptions still mention "28 finishes" (102, 1024, WP-2/16-GAL, 1098). Bobby flagged: "it ends with 28 finishes which is not great."

**What improved:** The hardcoded "28 finishes vs 4-12" competitive bullet was removed from prompt_builder.py. The model is no longer forced to include it.

**What still fails:** The model learned the pattern from skills/training and still voluntarily inserts "28 finishes" references. This needs to be an explicit prohibition in the accuracy guardrail when generating for specific variants.

## NEW Issues Discovered in Round 2

These are issues NOT present in Round 1 that the Plan 25-04 changes did not address — they were either hidden by other problems or are emergent from the refactored prompts.

### Issue A: "Die-cast zinc" / "plated alternatives" (CRITICAL — BOTH evaluators)

**Robert's words:** "I do not like the idea of 'common die-cast zinc' which I believe is not good for us. If that term is in our description I am worried about consumers finding us with that term."

**Bobby's words:** Flagged "plated alternatives" and "die-cast zinc alternatives" multiple times as problematic.

**Impact:** HIGH. This is a competitive positioning mistake: mentioning competitor materials by name risks Allied Brass products appearing in searches for cheap alternatives. Descriptions for 1016, 102, 1020-3, 1020, and 1098 all contain this language.

**Root cause:** The `allied-brass-brand-expert` skill teaches competitive positioning that contrasts solid brass with zinc/plated alternatives. The model is following the skill's guidance, but the skill's competitive framing is wrong — it names the competitor material rather than focusing on Allied Brass's positive differentiators.

**Fix:** Update the `allied-brass-brand-expert` skill to explicitly prohibit naming competitor materials. Competitive advantage should be framed positively: "solid brass that won't corrode, pit, or tarnish" — never "better than die-cast zinc."

### Issue B: Weight capacity inclusion (HIGH — Robert strongly opposed)

**Robert's words:** "I do not like the idea of a weight capacity in either Description and would rather have that removed. The weight capacity is generally not a problem on the wall hardware and this may just have a consumer stray from the product because of a stated weight limit."

**Impact:** MEDIUM-HIGH. Weight capacity appeared in descriptions for 1016, 1020-3, 1020, and WP-2/16-GAL. Robert sees this as a negative — it creates doubt about the product's strength rather than building confidence.

**Root cause:** The evidence table contains weight capacity data, and the model treats all evidence as potentially useful content. There's no instruction to EXCLUDE weight capacity from descriptions.

**Fix:** Add to accuracy guardrail: "Do NOT include weight capacity in descriptions — it creates consumer doubt rather than confidence. Weight capacity is better communicated in technical specifications."

### Issue C: Excessive dimensional information (HIGH — BOTH evaluators)

**Robert's words:** "Too much dimensional information. All of that detailed information can be gotten from the spec file that is on the listing."

**Bobby's words:** Multiple SKUs flagged for too many dimensions.

**Impact:** HIGH. Descriptions for 1020, 1025U, 1098, DMF-2/2X, WP-2/16-GAL, and CL-22 all had excessive dimensions. This clutters the description with technical data that belongs in the product spec sheet, not the marketing description.

**Root cause:** The evidence table is rich with dimensional data, and the model treats it as content to include. The creative direction says "lead with design detail" but doesn't distinguish between marketing-worthy dimensions (overall length of a towel bar) and spec-sheet dimensions (2.75 x 2.75 x 0.5 inches).

**Fix:** Add dimension guidance: "Include only the PRIMARY dimension that shoppers search for (e.g., overall length for towel bars, mirror diameter for mirrors). Exclude detailed measurements (width, height, projection) — these belong in the specification sheet. Only include dimensions when the product varies by size AND shoppers search by size."

### Issue D: "Heritage bathroom fixtures" (MEDIUM — BOTH evaluators confused)

**Bobby:** "heritage bathroom fixtures but I have no idea what that is."
**Robert:** "references 'heritage bathroom fixtures' which I do not understand."

**Impact:** MEDIUM. This phrase appeared in multiple descriptions (1025U, 1024). Neither evaluator understood it.

**Root cause:** The model invented or borrowed this term from training data. It's not in the product evidence or skills.

**Fix:** Add to banned phrases in SYSTEM_PROMPT brand_voice: "heritage bathroom fixtures" (along with existing banned words).

### Issue E: "Bathroom humidity" as selling point (MEDIUM — Bobby flagged)

**Bobby:** "bathroom humidity information... I don't think is a huge selling point for our product and is again one of those selling points that seems stretched and fluffy and made up."

**Impact:** MEDIUM. Multiple descriptions reference brass resisting "bathroom humidity" or "humid bathrooms." While technically accurate, it feels like filler.

**Root cause:** The model reaches for generic durability claims when it doesn't have strong product-specific differentiators. "Bathroom humidity" resistance is a logical but uninspiring extension of brass durability.

**Fix:** Deprioritize humidity as a selling point in the skills. It can be mentioned once if relevant but should never be a key differentiator.

### Issue F: Product type misidentification (CRITICAL — affects correctness)

**Robert on 1024:** "Title B has Euro Style and this product is a 2 post Toilet Paper Holder. Title B also should not have the dimension."
**Robert on 1020:** "Title A refers to the product as a Towel Hook and it should be referenced as a robe hook."

**Impact:** CRITICAL. Wrong product type = wrong search intent = wasted impressions. A "Euro Style" toilet paper holder is a fundamentally different product from a "2-post" holder.

**Root cause:** The evidence table may have ambiguous product type data, or the model is inferring product type from incomplete evidence. The product_catalog or variant_index may classify these products differently than how they should be marketed.

**Fix:** This requires data investigation. Check what product_type/category values exist in the evidence for 1024 and 1020. If the evidence is wrong, fix the source data. If the model is misinterpreting correct data, add stronger product type guidance.

### Issue G: "Also searched as..." keyword stuffing (MEDIUM — Bobby flagged)

**Bobby on CL-22:** "the last sentence started with 'also searched as,' which I don't think makes sense for a description because that kind of indicates that you're just doing this for the purposes of search."

**Impact:** MEDIUM. This makes the content feel like SEO manipulation rather than genuine product information.

**Root cause:** The keyword placement plan may be pushing keywords that the model then awkwardly appends as a list. The model needs to integrate keywords naturally, not as an explicit "also searched as" section.

**Fix:** Add to accuracy guardrail: "Never use 'also searched as,' 'also known as,' or similar keyword list patterns. All keywords must be integrated naturally into the description narrative."

### Issue H: Title structure rules missing (HIGH — Robert's expert feedback)

Robert provided specific title structure preferences that are NOT currently in the prompt:
1. **Finish name should be FIRST** in the title
2. **"Collection" keyword** should follow collection names (e.g., "Skyline Collection" not just "Skyline")
3. **Dimensions only when product varies by size** (towel bars: yes; robe hooks: no)
4. **"Solid Brass" not in prime position** — early title space is for converting keywords, not material
5. **Style references should vary** across products to capture different search terms
6. **Product function first** — "Multi Hook" should be near the beginning

**Fix:** Update the `google-shopping-content` skill with explicit title formula incorporating Robert's preferences. This is expert knowledge that the skill should codify.

## Systemic Root Causes (for future phases)

### Root Cause 1: Skills contain anti-patterns the model follows faithfully

The `allied-brass-brand-expert` skill teaches competitive positioning that names competitor materials ("die-cast zinc," "plated alternatives"). GPT-5.2 follows this guidance exactly — producing content that both evaluators reject. **The skills need to be updated, not just the SYSTEM_PROMPT scaffolding.**

Affected SKUs: 1016, 102, 1020-3, 1020, 1098, WP-2/16-GAL (6/10)

### Root Cause 2: No content EXCLUSION rules for evidence data

The model treats ALL evidence fields as potential content. But some evidence (weight capacity, detailed dimensions, installation specifics) belongs in spec sheets, not marketing descriptions. The prompt needs explicit exclusion rules for which evidence fields to omit.

Affected SKUs: 1016, 1020-3, 1020, 1025U, 1098, DMF-2/2X, WP-2/16-GAL, CL-22 (8/10)

### Root Cause 3: Title formula not codified from domain expertise

Robert has specific, expert opinions about title structure that are not in any skill or prompt. His preferences represent decades of selling Allied Brass products. These need to be codified in the `google-shopping-content` skill.

Affected SKUs: 1025U, 1020, 1098, CL-22, WP-2/16-GAL (5/10 — titles that lost)

### Root Cause 4: Product type classification in evidence data

The evidence table or model inference produces wrong product types (1024: "Euro Style" instead of "2-post"; 1020: "Towel Hook" instead of "Robe Hook"). This is a data quality issue that no amount of prompt engineering can fix — the source data needs correction.

Affected SKUs: 1024, 1020 (2/10 — but critical)

## Recommendations for Round 3

### Priority 1: Update skills (not just SYSTEM_PROMPT)

1. **`allied-brass-brand-expert` skill:** Remove ALL references to competitor materials by name. Replace with positive differentiators only. Add explicit prohibition: "Never mention die-cast zinc, plated alternatives, or any competitor material by name."

   - "Collection" keyword after collection names
   - Dimensions only when product varies by size
   - Style reference that varies across products
   - "Solid Brass" not in prime early position
   - "Allied Brass" as final segment

3. **`product-storytelling` skill:** Add evidence exclusion rules — weight capacity, detailed dimensions, installation specifics should be omitted. Focus on design story, not technical data.

### Priority 2: Add content prohibition rules to SYSTEM_PROMPT

Add to `<accuracy_guardrail>`:
- Do NOT include weight capacity in descriptions
- Do NOT include detailed dimensions (width, height, projection) — only primary searchable dimension
- Do NOT use "also searched as" or keyword list patterns
- Do NOT name competitor materials (die-cast zinc, plated alternatives)
- Do NOT use "heritage bathroom fixtures" or other invented phrases

### Priority 3: Fix product type data

Investigate evidence table for 1024 and 1020 to determine if product type classification is correct. If wrong, fix at the source.

### Priority 4: Reassess "28 finishes" rule

Currently only suppressed when `finish_code` is explicitly passed. Should be suppressed for ALL Google/Bing descriptions since they will be expanded to variant-specific listings.
