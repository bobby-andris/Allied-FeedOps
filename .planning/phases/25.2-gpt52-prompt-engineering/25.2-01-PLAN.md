**In `prompts.py`**, add 4 new schema constants alongside the existing CANDIDATE_SCHEMA (do NOT remove the existing schema — it's used by the current pipeline and must remain until Plan 02 wires the new architecture):

1. **GOOGLE_SCHEMA** — strict json_schema mode. Fields: `google_title` (string, max 150 chars, MUST start with {FINISH_NAME}), `google_short_title` (string, max 70 chars), `google_description` (string, 700-900 chars, must include literal `{FINISH_SENTENCE}` placeholder), `claims` (array of {claim, source_field, source_value}), `self_score` ({accuracy: int, specificity: int, engagement: int}).

2. **BING_SCHEMA** — Fields: `bing_title` (string, max 150 chars, MUST start with {FINISH_NAME}), `bing_description` (string, 700-1000 chars, front-load specs in first 200 chars, include literal `{FINISH_SENTENCE}`), `claims` (array), `self_score` (same).

3. **SHOPIFY_SCHEMA** — Fields: `shopify_title` (string, no finish name — finish-agnostic), `shopify_description` (string, HTML allowed, 250-400 words, buyer-problem-first opening, NO {FINISH_NAME}/{FINISH_SENTENCE}), `shopify_meta_description` (string, max 160 chars), `claims` (array), `self_score` (same).

4. **FINISH_SENTENCES_SCHEMA** — Fields: `sentences` (array of 28 items, each {finish_code: string, finish_name: string, sentence: string (40-80 chars, product-specific)}).

Each schema must follow strict mode conventions: `additionalProperties: false` at every object level (root AND all nested object property levels), all properties in `required` array. Use the existing `_build_strict_schema()` pattern from `openai_provider.py` as reference. For nested objects (e.g., `claims` items, `self_score`, `sentences` items), ensure `additionalProperties: false` is set at EACH nested object level — a missing nested `additionalProperties` will cause GPT-5.2 strict mode to reject the schema at API call time.

**In `skill_loader.py`**, add a new function `get_platform_system_prompt(platform: str) -> str` that:

1. Reads a PLATFORM_SKILL_MAP dictionary mapping platforms to their relevant skills:

   - `"shopify"` → `["shopify-conversion-content", "allied-brass-brand-expert", "product-storytelling", "collection-storytelling"]`
   - `"finish"` → `["finish-expertise", "collection-storytelling", "product-storytelling"]`

2. For each skill, extracts ONLY the actionable knowledge sections (not interactive Claude Code guidance). Read each SKILL.md file, then extract content between XML tags like `<rules>`, `<examples>`, `<formula>`, `<constraints>`, `<brand_voice>`. If the skill doesn't use XML tags, extract the most relevant sections (title formula, gold examples, brand voice rules, finish descriptions). Target: ~2-4K chars extracted per skill.

3. Assembles a platform-specific system prompt with this structure:
   ```
   <role>You write {platform} content for Allied Brass solid brass bathroom hardware.</role>
   <brand_voice>[extracted from allied-brass-brand-expert]</brand_voice>
   <platform_rules>[extracted from platform-specific skill]</platform_rules>
   <accuracy>[shared accuracy rules]</accuracy>
   ```

4. Keep the existing `get_system_prompt()` function unchanged — it's used by the current production pipeline. The new `get_platform_system_prompt()` is additive.

**Key design principle per CONTEXT.md:** Do NOT assume skills need to be distilled or abandoned. The Agent Skills format is designed for any LLM. Extract the actionable knowledge but test empirically whether the format helps GPT-5.2. The platform system prompts should be kept under ~8K tokens each initially — but adjust based on test results in Task 2.
