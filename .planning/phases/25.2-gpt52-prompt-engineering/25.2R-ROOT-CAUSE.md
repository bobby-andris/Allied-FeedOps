## Root Causes (Methodology Issues)

### RC-1: Evidence Contamination (RESOLVED by post-normalization)

**Problem:** Manufacturer bullet_1 contains "finest solid brass materials", keyword data contains "jan barboglio". GPT-5.2 copies these verbatim.

**Status:** RESOLVED. The post-generation normalization pipeline now:
- `_remove_banned_words()` strips "finest" and other banned words
- `_sanitize_platform_description()` removes entire sentences containing competitor brands or banned phrases
- `_SKILL_LINE_BANLIST` in skill_loader.py prevents banned phrases from entering system prompt via skill extraction

**Remaining gap:** Shopify descriptions only get `_remove_banned_words()`, NOT sentence-level `_sanitize_platform_description()`. If GPT-5.2 writes "If you're searching for jan barboglio..." in a Shopify description, only the banned word filter runs — the competitor mention would survive. **This is a minor gap** because Shopify descriptions are master-SKU level and keyword data (the source of competitor names) is less prominent in Shopify prompts.

### RC-2: "28 Finishes" Count in Descriptions (PARTIALLY RESOLVED)

**Problem:** Bobby flagged: "ends with a generic 28 finishes which is not great." The system prompt (prompts.py:353) says "Do NOT mention 28 finishes or finish variety counts in Google/Bing descriptions."

**Status:** The prompt instruction is there. The post-generation normalization does NOT explicitly strip "28 finishes" sentences. In 25.2's 6-SKU test, this did NOT appear (the per-platform prompts are more focused and GPT-5.2 follows the instruction better). However, there's no deterministic guarantee.

**Fix needed:** Add to `_DESCRIPTION_SENTENCE_BANNED_PATTERNS` in generator.py:
```python
re.compile(r"\b28\s+(?:designer\s+)?finish(?:es)?\b", re.IGNORECASE),
```

### RC-3: Advisory Checks Treated as Hard Failures (RESOLVED)

**Problem:** The test harness was treating google_description 700-900 char range as a hard failure, making content that was 680 chars look like it failed.

**Status:** RESOLVED in current code. `evaluate_platform_output()` in ab_prompt_test.py correctly marks `description_length_recommended_700_900` with `severity="advisory"`, while `description_length_max_5000` is hard. The reporting distinguishes them.

### RC-4: No Post-Normalization for Shopify Descriptions (MINOR GAP)

**Problem:** Runtime normalization for Shopify applies only `_remove_banned_words()` and `_align_subtype_terms()`, not the full `_sanitize_platform_description()`. This means competitor mentions, banned phrases, and weight capacity could survive in Shopify HTML descriptions.

**Status:** Low risk because:
1. Shopify prompts don't include keyword data (the main source of competitor names)
2. Per-platform system prompts are more focused, reducing contamination
3. Shopify descriptions are master-SKU, finish-agnostic — less evidence pollution

**Fix needed (low priority):** Add a `_sanitize_shopify_description()` that strips competitor/banned-phrase sentences from HTML while preserving structure.

### RC-5: Skill Knowledge Not Reaching GPT-5.2 Effectively (RESOLVED)

**Problem:** Bobby said "it doesn't seem like those skills are actually being used." The old pipeline dumped all 267K chars of 8 skills into every call.

**Status:** RESOLVED. `get_platform_system_prompt()` now:
1. Loads only platform-relevant skills (3-4 per platform, not 8)
2. Extracts actionable sections via `extract_actionable_skill_knowledge()` with section selection
3. Sanitizes extracted content via `_sanitize_extracted_knowledge()` to remove banned lines
4. Assembles structured XML prompt (~7-8K chars per platform)

The 25.2-03 comparison document shows qualitatively better content that reflects skill knowledge (collection descriptions, buyer-problem openings, design language).
