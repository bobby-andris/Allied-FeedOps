Active Jobs section (two separate sections):
1. "Search Term Sync Jobs" section:
   - Reads from /api/monitoring/sync-jobs

   - Should show the Phase 15-01 sync jobs (smoke test + full backfill)

2. "Performance Backfill Jobs" section:

   - Should show the Phase 15-02 backfill job

## Coverage API
GET https://feedops-pipeline-623866089882.us-east1.run.app/monitoring/coverage

Response fields (per 14-03-SUMMARY.md):
- `total_skus`: distinct master_skus in variant_index
- `search_terms_sku_coverage`: distinct master_skus in search_queries
- `search_terms_offer_coverage`: distinct gmc_offer_ids in search_queries
- `total_offer_ids`: distinct gmc_offer_ids in variant_index
- `performance_baselines_coverage`: distinct master_skus in performance_baselines

## If coverage numbers look wrong
Run the monitoring coverage API directly and compare to Supabase ground truth:
```bash
curl -s https://feedops-pipeline-623866089882.us-east1.run.app/monitoring/coverage | python3 -m json.tool
```
Then verify with Supabase:
```sql
SELECT COUNT(DISTINCT master_sku) as sq_skus FROM search_queries;
SELECT COUNT(DISTINCT master_sku) as pb_skus FROM performance_baselines;
```

## Login credentials
The dashboard requires authentication. agent-browser should handle the session if already logged in.
If not logged in: navigate to /login, use existing session or check .env.vercel for credentials.
