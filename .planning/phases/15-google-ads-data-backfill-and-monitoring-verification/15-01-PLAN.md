<objective>
Add start_date/end_date/filter_skus to sync endpoint, validate with strategic test SKUs, then run chunked 180-day backfill.

Purpose: Three problems with the original plan:
1. The sync endpoint hardcodes "today minus N days" — no way to target historical windows, making 180-day chunked backfill impossible
2. Smoke tests were account-wide, meaning a failure could be anywhere in 2,784 SKUs — impossible to debug efficiently
3. A single 180-day call risks timeout with no progress verification

New approach:
1. Add start_date/end_date to enable explicit chunked windows (6 × 30 days = 180 days of true historical data)
2. Add filter_skus to enable targeted smoke tests with specific SKUs we understand
3. Write a selection script to pick strategic test SKUs from Google Ads data (not just any 5 SKUs)
4. Validate end-to-end data quality with test SKUs before committing to full backfill
5. Run chunked 180-day backfill, verifying row count growth after each window

Output: search_queries table with validated historical data across 180 days; all new rows have synced_at set;
monitoring coverage card shows >> 125 distinct SKUs.
</objective>
