  <action>
Create new file `src/feedops/api/monitoring.py` with a FastAPI APIRouter(prefix="/monitoring", tags=["Monitoring"]).

**Endpoint 1: GET /monitoring/freshness (MON-03)**
- Query `variant_index` for distinct master_sku list
- For each SKU, query latest `collected_at` from `search_queries`, latest `captured_at` from `performance_baselines`, and latest non-null `keyword_metrics_collected_at` from `search_queries`
- IMPORTANT: Use efficient SQL via `execute_sql` MCP pattern or Supabase client — do NOT loop per-SKU. Instead, use SQL aggregation:
  ```sql
  SELECT vi.master_sku,
    MAX(sq.collected_at) as search_terms_latest,
    MAX(pb.captured_at) as performance_latest,
    MAX(sq.keyword_metrics_collected_at) as keywords_latest
  FROM (SELECT DISTINCT master_sku FROM variant_index) vi
  LEFT JOIN search_queries sq ON sq.master_sku = vi.master_sku
  LEFT JOIN performance_baselines pb ON pb.master_sku = vi.master_sku
  GROUP BY vi.master_sku
  ```
- Calculate age_days = (now - latest_timestamp).days for each, defaulting to 999 if null
- Return: `{"freshness": [{"master_sku": "...", "search_terms_age_days": N, "performance_age_days": N, "keywords_age_days": N}, ...]}`

**Endpoint 2: GET /monitoring/coverage (MON-02)**
- Count total distinct master_skus in variant_index
- Count distinct master_skus with at least one row in search_queries
- Count distinct master_skus with at least one row in performance_baselines
- Count distinct master_skus with non-null keyword_metrics_collected_at in search_queries
- Return: `{"total_skus": N, "search_terms_coverage": N, "performance_coverage": N, "keywords_coverage": N}`

**Endpoint 3: GET /monitoring/api-health (MON-04)**
- Import `metrics_registry` from `feedops.observability.metrics`
- Call `metrics_registry.snapshot()` to get current counters and timings
- Extract http_request_error_total, http_request_latency_seconds, provider_error_total
- For latency, calculate p95 from the timings list (sort + index at 95th percentile)
- Return: `{"error_count": N, "provider_errors": N, "latency_p95_ms": N, "rate_limit_hits": N, "sample_size": N}`
- For rate_limit_hits, look for counter key containing "rate_limit" in metrics_registry counters

Use Pydantic response models for all endpoints (FreshnessResponse, CoverageResponse, ApiHealthResponse).
Check `docs/database/SCHEMA.md` for exact column names before writing queries.
