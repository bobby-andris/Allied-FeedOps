Root cause: The coverage and freshness endpoints use `supabase.rpc("execute_sql", {"query": ...})` which calls a custom RPC function. The RPC function returns JSONB, but the Supabase Python client wraps RPC results differently than table queries. `result.data` from `.rpc()` calls contains the raw JSONB return (a single JSON value), not a list-of-dicts like `.table().select().execute()` returns. This causes a data structure mismatch when monitoring.py tries to iterate `result.data` as if it were rows.

The api-health endpoint does NOT use the database (reads from in-memory metrics_registry), but may have been dragged down by an unhandled import or the same 500 error was assumed without independent testing.

Fix approach: Replace ALL `execute_sql` RPC calls with direct Supabase table queries using the standard `client.table().select()` pattern that works reliably everywhere else in the codebase (see supabase_client.py for 40+ working examples of this pattern). Add try/except error handling to each endpoint so individual failures don't cascade.
</context>

**Coverage endpoint (`get_data_coverage`):**
Replace the 4 separate `supabase.rpc("execute_sql", ...)` calls with:

1. Total SKUs: `supabase.table("variant_index").select("master_sku")` then count distinct values in Python. OR use `supabase.table("variant_index").select("master_sku", count="exact")` if distinct not needed (all rows have master_sku).
   - Better approach: `supabase.table("variant_index").select("master_sku").execute()` then `len(set(row["master_sku"] for row in result.data))` for distinct count.

2. Search terms coverage: `supabase.table("search_queries").select("master_sku").not_.is_("master_sku", "null").execute()` then count distinct.

3. Performance coverage: `supabase.table("performance_baselines").select("master_sku").execute()` then count distinct.

4. Keywords coverage: `supabase.table("search_queries").select("master_sku").not_.is_("keyword_metrics_collected_at", "null").execute()` then count distinct.

**Freshness endpoint (`get_data_freshness`):**
Replace the single `supabase.rpc("execute_sql", ...)` call with multiple direct queries:

1. Get all distinct master_skus: `supabase.table("variant_index").select("master_sku").execute()`
2. Get search_queries freshness: `supabase.table("search_queries").select("master_sku, collected_at").execute()`
3. Get performance freshness: `supabase.table("performance_baselines").select("master_sku, captured_at").execute()`
4. Get keyword freshness: `supabase.table("search_queries").select("master_sku, keyword_metrics_collected_at").not_.is_("keyword_metrics_collected_at", "null").execute()`
5. Compute ages in Python by grouping by master_sku, finding MAX timestamp per SKU, then calculating days since now.

Use `datetime.now(timezone.utc)` for age calculations. Convert ISO timestamp strings with `datetime.fromisoformat(ts.replace("Z", "+00:00"))` if needed.

**IMPORTANT**: Check `docs/database/SCHEMA.md` for exact column names before writing queries. Key columns:
- `search_queries`: `master_sku`, `collected_at`, `keyword_metrics_collected_at`
- `performance_baselines`: `master_sku`, `captured_at`
- `variant_index`: `master_sku`

Also wrap each endpoint body in try/except with logger.exception() and return a 500-level HTTPException with the error message, so failures are visible in Cloud Run logs instead of generic 500s.
