**POST /api/bottleneck/classify:**

Create `dashboard/src/app/api/bottleneck/classify/route.ts`:

Accept query params: `master_sku` (required), `override_by` (optional), `override_note` (optional), `override_classification` (optional).

If `override_classification` is provided, insert a manual override row (is_override=true) and return early.

Otherwise, implement the decision tree classifier. The classifier runs these checks IN ORDER (first match wins):

1. **coverage_gap** (confidence 0.95): No row in `generated_content` for this master_sku
2. **code_path_gap** (confidence 0.90): Content exists in `generated_content` but no `publish_events` row with status='success'
3. **propagation_failure** (confidence 0.85): Published (publish_events success exists) but `performance_snapshots` with days_since_publish > 7 shows 0 impressions
4. **query_relevance** (confidence 0.75): `keyword_coverage_master` has >2 rows where `in_title = false` AND `query_volume > 100` for this SKU
5. **auction_bid** (confidence 0.60): Default fallback — impressions exist but IS lost to rank

Each check queries Supabase using the service role client. Build an `evidence` JSONB object documenting what was checked and the result.

Upsert to `sku_bottleneck_classifications` with `on_conflict` on `master_sku` (using the partial unique index where `is_override = false`). For auto-classifications, set `is_override = false`.

Also support `POST /api/bottleneck/classify?batch=true` (no master_sku) which classifies ALL SKUs that have any content in generated_content. Use a chunked approach — fetch all master_skus from generated_content, classify each, batch upsert results.

Return: `{ master_sku, classification, confidence, evidence, is_override }`.

Handle null/empty data defensively per Pitfall 4 in research — if a query returns no rows, that's a signal (coverage_gap), not an error.

**GET /api/bottleneck/status:**

Create `dashboard/src/app/api/bottleneck/status/route.ts`:

Accept query params: `master_sku` (optional, filters to one SKU), `classification` (optional, filters by category), `limit` (optional, default 100).

Query `sku_bottleneck_classifications` with applied filters. Order by `classified_at DESC`. Join with override rows if they exist (prefer override over auto).

Return: `{ classifications: [...], total_count, by_category: { coverage_gap: N, code_path_gap: N, ... } }`.

Include the category summary counts regardless of filters.

Use the standard Supabase client pattern from other API routes in the project (check `dashboard/src/app/api/` for import patterns — `createClient` from `@/lib/supabase/server`).

**GET /api/prompt-lineage:**

Create `dashboard/src/app/api/prompt-lineage/route.ts`:

Accept query params: `master_sku` (required), `platform` (optional, default 'google').

Query chain:
1. Get latest successful publish_event for this master_sku + platform, selecting `id, published_at, prompt_hash, content_version`
2. If `prompt_hash` is NULL (historical data before lineage tracking), return `{ lineage: null, note: 'Prompt hash not recorded for this publish event — lineage tracking available for content published after Phase 19' }`
3. If prompt_hash exists, look up `prompt_version_aliases` for a human-readable alias
4. Query `regeneration_history` for the matching master_sku + platform + prompt_hash to get `created_at, model_version, feature_flags_active, quality_score_after, tokens_used, latency_ms`

Return:
```json
{
  "publish_event_id": 123,
  "published_at": "2026-02-20T...",
  "prompt_hash": "abc123...",
  "prompt_alias": "v2.1" | null,
  "prompt_notes": "Added Shopping intelligence" | null,
  "generation": {
    "generated_at": "...",
    "model_version": "gpt-5.2",
    "feature_flags_active": {...},
    "quality_score": 87.2,
    "tokens_used": 1500,
    "latency_ms": 3200
  } | null
}
```

Also support `compare=true&hash_a=X&hash_b=Y` mode for opt-in side-by-side comparison (per user decision: "opt-in, not default view"). When compare=true:
- Query regeneration_history for both hashes for the given master_sku+platform
- Return both generations with their metadata for side-by-side display

Use the same Supabase client pattern as the classify route.
