<objective>
Rewrite the SYSTEM_PROMPT from a compliance document into a creative brief and build a unified skill loader that injects full Claude Code skill content into generation prompts.

Purpose: The current SYSTEM_PROMPT leads with restrictions (P0/P1/P2 priority rules, accuracy guardrails, banned words) which causes GPT-5.2 to generate compliance-first, creativity-last content. The new prompt opens with creative direction — what great Allied Brass content sounds like — and moves accuracy guardrails lower. Additionally, the 8 runtime YAML configs are thin distillations of rich skill files (5-10x more content). Loading full skills into prompts dramatically improves first-pass quality, especially for batch runs where the system prompt is cached across all SKUs.

Output: Rewritten SYSTEM_PROMPT, new skill_loader.py module, updated prompt_builder.py with skill injection.
</objective>

**Part B: Create `src/feedops/pipeline/skill_loader.py`**

Create a new module that loads skill SKILL.md files from disk and caches them. Pattern follows `shopping_intelligence.py` (lru_cache for container lifetime).

```python
"""Unified skill loader for runtime prompt injection.

Loads full Claude Code skill SKILL.md files and injects them into generation
prompts. Skills are 5-10x richer than YAML config distillations and produce
higher first-pass quality content.

Architecture:
- Skills loaded from .claude/skills/{name}/SKILL.md relative to project root
- For Cloud Run deployment: skills are copied into the container image
- lru_cache ensures single load per container lifetime
- Adaptive loading: batch mode loads ALL skills into system prompt (cached
  across all SKUs); single-SKU mode loads core + platform-relevant skills

Public API:
    load_skill_content(skill_name: str) -> str | None
    load_skills_for_prompt(mode: str, platform: str | None) -> str
"""
```

Implement:

1. `_find_skills_dir() -> Path | None` — Locate the skills directory. Try multiple paths in order:
   - `Path(__file__).parent.parent.parent.parent / ".claude" / "skills"` (dev: src/feedops/pipeline -> project root)
   - `Path("/app/.claude/skills")` (Cloud Run container)
   - Return None if neither exists (graceful degradation)

2. `@lru_cache(maxsize=32) load_skill_content(skill_name: str) -> str | None` — Load a single skill's SKILL.md content. Return None if file not found. Log warning on missing file.

3. `load_skills_for_prompt(mode: str = "batch", platform: str | None = None) -> str` — Assemble skill content for prompt injection.

   **Core skills (always loaded in both modes):**
   - `allied-brass-brand-expert` — brand voice and competitive positioning
   - `quality-evaluation` — 10-criterion rubric with anchors and examples
   - `product-storytelling` — interior designer perspective, scenarios, emotional resonance

   **Platform skills (loaded based on platform param or all in batch mode):**
   - `google-shopping-content` — loaded when platform is "google" or mode is "batch"
   - `bing-shopping-content` — loaded when platform is "bing" or mode is "batch"
   - `shopify-conversion-content` — loaded when platform is "shopify" or mode is "batch"

   **Conditional skills (loaded when applicable):**
   - `finish-expertise` — always loaded (finish integration is universal)
   - `collection-storytelling` — always loaded (collection coordination is universal)

   Format output as XML-tagged sections:
   ```
   <skill name="allied-brass-brand-expert">
   {content}
   </skill>

   <skill name="google-shopping-content">
   {content}
   </skill>
   ```

   In "single" mode with a specific platform, skip non-relevant platform skills to reduce token cost for single-SKU regeneration. In "batch" mode, load ALL skills (the system prompt is cached across all SKUs so the cost is amortized).

4. Add a fallback: if `_find_skills_dir()` returns None (skills not available), log a warning and return empty string. The YAML configs remain as the backup injection path in prompt_builder.py.

**IMPORTANT for Cloud Run deployment:** The skills directory needs to be copied into the Docker container. Add a comment at the top of the module noting this requirement. The actual Dockerfile change will be handled as part of the deployment step (not this task — just document the need).

**Part A: Update `prompt_loader.py` — `get_system_prompt()` to include skills**

Modify `get_system_prompt()` to accept an optional `mode` and `platform` parameter and append loaded skills to the system prompt:

```python
def get_system_prompt(mode: str = "batch", platform: str | None = None) -> str:
    """Get the canonical system prompt enriched with skill content.

    Args:
        mode: "batch" loads all skills (cached across SKUs), "single" loads
              core + platform-relevant skills only.
        platform: Target platform for single mode ("google", "bing", "shopify").

    Returns:
        System prompt string with skill sections appended.
    """
```

After getting the canonical `SYSTEM_PROMPT` (or DB fallback when PROMPT_CONTRACT_V2 disabled), append loaded skills:

```python
if skill_content:
    prompt = prompt + "\n\n" + skill_content
```
