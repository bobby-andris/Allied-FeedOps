Status labels:
- WORKING — page loads, data shows, no dead ends
- STALE — loads but data is misleading, outdated, or incorrect
- BROKEN — page errors, API fails, or critical path does not work
- DEAD-END — page loads but has empty state with no path forward or action
- LOW-VALUE — page works but rarely serves the current workflow (flag only, do not change)

Actions:
- KEEP — working, no change needed
- FIX — specific issue to address in plan 12-02
- REMOVE — feature is broken AND has no future value
- SIMPLIFY — reduce scope to what's actually used
- EMPTY-STATE — add contextual empty state with action

For each dashboard page listed in context, perform a code-level audit:

1. **Read the page file** — understand what it renders, what data it fetches, what API routes it calls
2. **Read the relevant API routes** — check if they return real data or are stubs/broken

4. **Check for UX anti-patterns** — `alert()`, `console.error` only error handling, no loading states
5. **Assess status** — assign one of: WORKING, STALE, BROKEN, DEAD-END, LOW-VALUE
