CREATE TABLE IF NOT EXISTS performance_impact_scores (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,

  platform text NOT NULL,

  sample_size_control integer NOT NULL DEFAULT 0,
  window_pre_days integer NOT NULL DEFAULT 30,
  window_post_days integer NOT NULL DEFAULT 30,
  run_date date NOT NULL,
  computed_at timestamptz NOT NULL DEFAULT now()
);

**FEED-03 wiring:** The existing `/api/monitoring/snapshot-capture/route.ts` handles writing search query snapshots, but nothing calls it after a publish event. Without this, Plan 03's search term delta view will return empty data for all new publishes.

**In `publish/sku/route.ts`:**
After the successful publish event insert (after the supabase insert returns successfully), add a fire-and-forget call to capture a search query snapshot:
```typescript
// FEED-03: Capture search query snapshot after publish for term delta analysis
// Fire-and-forget — don't block the publish response on snapshot capture
try {
  const baseUrl = process.env.NEXT_PUBLIC_APP_URL || process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : 'http://localhost:3000'
  fetch(`${baseUrl}/api/monitoring/snapshot-capture`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ master_sku: event.master_sku, trigger: 'post-publish' }),
  }).catch(err => console.error('[FEED-03] Snapshot capture failed (non-blocking):', err.message))
} catch (err) {
  console.error('[FEED-03] Snapshot capture trigger failed (non-blocking):', err)
}
```

**Important:** This MUST be fire-and-forget. The publish response should not wait for snapshot capture to complete. Use `.catch()` on the fetch promise to swallow errors — snapshot capture failure should never block a successful publish.

**In `publish/batch/route.ts`:**
